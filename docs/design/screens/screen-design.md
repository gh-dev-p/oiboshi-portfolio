## 1. 本書の目的・範囲

- 画面ごとの役割・入口・構成要素・入力・遷移・異常系を定める。
- 画面の項目・構成・遷移・バリデーション・異常系は、本書が正。見た目は Figma が正。
- 機能の詳細（処理フロー、取得方式）は扱わない。取得方式は platforms.md、決定事項は decisions.md を参照する。
- 画面IDは振らない。画面は名前で呼ぶ（決定事項）。

## 4. 画面遷移図

- 遷移図は FigJam に置く：追星 画面遷移図
- 主な遷移は、各画面の `<kbd>遷移</kbd>` に書く。大きな流れは次のとおり。

| 起点 | 流れ |
| --- | --- |
| 初回起動 | ウェルカム → 推しを選ぶ → 通知の説明 → ホーム。初回起動を済ませたあとは、起動するとホームを出す |
| 発信者の登録 | ウェルカムの「発信者の方はこちら」、または設定の「発信者として登録する」→ 発信者として登録 → SNS の連携・プロフィールの編集・プラン → 登録 → 前の画面（ウェルカム、または設定。下部ナビに、発信者のタブが出る） |
| タブ | 下部ナビで、ホーム・タイムスケジュール・推しリスト・設定（発信者は、設定の代わりに発信者のタブ）を切り替える。画面は、どのタブから押しても、受け持ちのタブで開く（5.1.8） |
| 設定 | 下部ナビの設定（発信者は、発信者メニューの右上の歯車）→ 各設定画面 |
| 発信者向け | 下部ナビの発信者のタブ（発信者メニュー）→ 各画面 |
| 配信開始の通知 | 通知を押す（またはアプリを開いているときのスナックバーの「開く」）→ 推しのタブに発信者ページ |

### 5.1 共通ルール

#### 5.1.1 下部ナビ

| 項目 | 内容 |
| --- | --- |
| タブ | ホーム、スケジュール、推しリスト、設定の4つ。この順に並べる。発信者として登録した人は、設定の代わりに、発信者のタブ（発信者メニュー。画面定義書（設定・発信者向け）2.2.2）を左端に置き、設定は発信者メニューの右上の歯車から開く |
| 固定ビューアのスイッチ | 固定ビューア（画面定義書（ファン向け）2.4.3、機能仕様書 4.3.5）を出し消しするスイッチ。タブではない。押すたびに入れる・切るを切り替え、入れているかを見分けられるようにする。はじく向きで固定ビューアを操作する「コントローラー」を兼ねる（上＝再生・停止、上右＝動画シャッフル、上左＝配信、右＝次、左＝前。触れたらすぐ、アイコンの周りに向きのヒントを出す。決まりは機能仕様書 4.3.5）。動画シャッフルのときは、右・左に引っ張ったまま止めると、早送り（右）・巻き戻し（左）。右・左の向きが決まって（36pt）から 0.4 秒、右・左のまま離さなければ引っ張ったまま止めたとみなし、1回振動する。それより早く離せば、次・前（払う）。速さは1秒に5秒分から、1秒ごとに 10・20・40・60 秒分。数字や位置の帯は出さず、固定ビューアの動画そのものが進む・戻る。離したら、そこから再生する（2026-11-19 本人。決まりは機能仕様書 4.3.5）。初めの状態は、推しが0人なら切、1人以上なら入（ユーザーが切ったら、開き直しても切ったまま）。推しの誰かが配信中のあいだは、触れて出るヒントの上左（配信）のアイコンの右上に小さな赤い点（ライブの色）を出し、スイッチのアイコンにも左上に同じ点を出す（2026-11-18 本人、場所は 2026-11-19 本人）。推しに新しい動画があるあいだは、上右（動画シャッフル）のアイコンの右上に、同じ形の点をホームの「NEW」の色で出し、スイッチのアイコンにも右上に同じ点を出す（両方あれば両方。2026-11-19 本人）。決まりは機能仕様書 4.3.5 |
| 表示 | 文字は出さず、アイコンだけにする（決定事項 5）。選んだタブを、ひと目で分かるようにする。推しリストは星、設定は歯車、固定ビューアのスイッチは再生の画面の形、発信者のタブは自分の発信者のアイコン（画像がなければ人の形） |
| 読み上げ | 各タブにタブの名前（「ホーム」「スケジュール」「推しリスト」「設定」「発信者メニュー」）、スイッチに「固定ビューア」を付ける |
| 形 | iOS の「写真」の下部メニューに合わせる（大きさ・位置は Figma とコードが正）。画面の下に浮かべ、中身は下部ナビの後ろまで流れる（いちばん下の中身が隠れないよう、下に余白を取る）。左から、切り離した丸を2つと、3つのタブをまとめた楕円を置く。発信者でなければ「ホーム・固定ビューアのスイッチ・楕円（スケジュール・推しリスト・設定）」。発信者は「発信者のタブ・固定ビューアのスイッチ・楕円（ホーム・スケジュール・推しリスト）」（設定は発信者メニューから開く。2026-11-17 本人）。楕円と丸は、後ろの中身が透けるすりガラス |
| スクロール | 下にスクロールすると縮小し、上にスクロールするか、いちばん上まで戻ると、元の大きさに戻る。縮小しても完全には隠さず、タブは押せる（決定事項 5）。縮小すると、楕円は3つのタブのまま小さくし、丸と楕円をまとめて中央に並べる |
| 出す画面 | タブと、タブの中で開く画面（5.1.8）。シートを開いているあいだは、シートを下部ナビの前に重ね、下部ナビを覆う（シートの下の操作が、下部ナビに隠れないようにするため） |
| 出さない画面 | 投稿ビューア、初回起動の画面 |
| キーボード | キーボードを出しているあいだは、キーボードの後ろに残し、余白も取らない |
| 同じタブを押す | そのタブの最初の画面に戻る。ホームの最初の画面にいるときは、いちばん上までスクロールする。スケジュールは、最初の画面に戻ったうえで、今日の今の時刻を表の真ん中へ移す（[画面定義書（スケジュール）](screen-design-schedule.md) 2.1.1。発信者のナビの楕円の中のスケジュールも同じ。2026-11-18 本人） |
| 横に払う | タブは移らない。タブは下部ナビだけで切り替える（スケジュールの横の操作（表の横スクロール、週の切り替え、横のピンチ）と取り違えないため） |

#### 5.1.2 ヘッダー

- 押して入る画面は、左に戻る、中央にタイトルを置く。違う画面（ヘッダーを置かない発信者ページ、左が閉じるの「ページから読み取る」など）は、各画面に書く。
- タブの本体は、左にタイトルを置く。ホームは、中央に追星のロゴを置く（画面定義書（ファン向け）2.2.1）。固定ビューア（画面定義書（ファン向け）2.4.3）を出している間は、ホームのヘッダーを出さない（固定ビューアが上に据わるので、縦を空ける）。
- ヘッダーは、ふだんは上に固定し、中身だけをスクロールする。固定ビューアを出している間は、縦が狭いので、ヘッダー（と、検索フィールドなどヘッダーのすぐ下に固定しているもの）を固定せず、中身と一緒にスクロールして上に隠す（いちばん上まで戻すと、また見える）。中身を下までスクロールしているときに固定ビューアを出したら、ヘッダーは隠れたところから始める。タブの本体（推しリスト・発信者メニュー・設定）と、押して入る画面のすべてに当てはめる（2026-11-09 本人）
  - 固定したままにするのは、タイムスケジュール（[画面定義書（スケジュール）](screen-design-schedule.md) 2.1.1）だけ。ただし、固定ビューアを出している間は、年月のヘッダーを出さず、右の3つのアイコンを表の右下に浮かせる（2026-11-18 本人）。そこから開く月のカレンダー・イベント一覧・イベントの詳細は、ほかの画面と同じく固定しない（2026-11-09 本人）
  - 「ページから読み取る」（Web のページを出す画面）は、固定したままにする（ページの中のスクロールは、ヘッダーに連動できないため）
- 見出しは、原則置かない。置くのは、面の見出し（ホームと発信者ページの「次の予定」「イベント」）や、一覧の節の見出し（推しを探すの「おすすめ」、設定のグループなど）のように、各画面の項に書いたものだけにする。
- 設定は、下部ナビのタブにする（ヘッダーに歯車は置かない）。発信者は、下部ナビに設定の丸がないので、発信者メニューのヘッダーの右に歯車を置き、設定のタブへ移る。

#### 5.1.3 状態表示

- 試作の画面（画面一覧の状態が「実装済み（試作）」のもの）と、【仮】の画面は、この節の対象外とする。作り込みは後回しにする。

<kbd>読み込み中</kbd>

- 画面の形に合わせたスケルトンを出す。画面全体の読み込みには、くるくる回る表示を使わない。

<kbd>空</kbd>

- イラスト・一言・次の操作のボタンを、画面の中央に出す。
- 検索の結果なしは、検索した言葉を入れて出す。ボタンは置かない。

<kbd>異常系</kbd>

- 初めて読み込めない　→　画面の中央に、イラスト・「読み込めませんでした」・「もう一度試す」を出す
- 表示済みの内容があるときの更新の失敗　→　内容を残したまま、下にスナックバー（「更新できませんでした」と「再試行」）を出す
- 操作の失敗（保存・フォロー・削除など）　→　スナックバーで知らせる
- スナックバーの形：横幅いっぱいにせず、文字の長さに合った幅で、画面の中央に出す。長い文は、画面の端から少し内側（左右 15）までで折り返す。操作（「再試行」など）は、文の右に並べる
- 取り消しにくい操作（削除・解除・解約・表示しない）　→　先に確認のダイアログを出す

<kbd>文言</kbd>

- 状態表示・スナックバー・ダイアログの文言は、日本語と英語を一緒に決め、ARB の両方に入れる（[i18n設計書](../architecture/i18n-design.md)）。英語は、日本語の直訳ではなく、英語の画面として自然な短い文にする。

#### 5.1.4 一覧の読み直し

- 表示中の一覧は、1分ごとに読み直す。リアルタイムの購読は使わない（決定事項 2）。
- 読み直すのは、推しの今を見る一覧（ホーム、タイムスケジュール、推しリスト、発信者ページなど）だけにする。推しを探す（おすすめ・検索の結果）、表示しない発信者、イベントの管理、投稿の管理は、読み直さない。自分の操作でしか変わらず、読み直すとサーバーの費用だけが増えるため。

#### 5.1.5 フォローのボタン

- 未フォローは「フォロー」、フォロー中は「フォロー中」を出す。押すと切り替える。
- 推しリスト、推しを探す、推しを選ぶ、発信者ページで、同じ文言にする。

#### 5.1.6 通知を受けたとき

配信開始の通知（機能仕様書 4.3.3）、予定の事前通知（届ける・広める仕様書 4.1.1）、追いたいの人の登録の通知（4.5.2）。


- 通知を押した　→　アプリを開き、タブの上に重ねた画面（投稿ビューア・ダイアログ・シートなど）を閉じて（タブの中で開いた画面は残す）、推しのタブに、その発信者のページを開く（5.1.8）。初回起動の途中なら、ホームに着いてから開く
- 追いたいの人の登録の通知を押した　→　配信開始の通知と同じく、推しのタブに、その発信者のページを開く
- 予定の事前通知を押した　→　同じく重ねた画面を閉じて、いま見ているタブの上に、その予定の詳細（シート。[画面定義書（スケジュール）](screen-design-schedule.md) 2.1.5）を開く。予定がもう消えていれば、推しのタブに、その発信者のページを開く。初回起動の途中なら、ホームに着いてから開く
- アプリを開いているときに届いた　→　OS の通知は出さず、いま見ているタブの画面の下に、スナックバー（通知のタイトル「{発信者の名前}が配信を始めました」。タイトルがなければ「推しが配信を始めました」、予定の事前通知なら「推しの予定のお知らせ」、追いたいの人の登録の通知なら「追いたい人が追星に来ました」。と「開く」）を出す。「開く」で、押したときと同じ画面を開く。タブの上に重ねた画面（投稿ビューアなど）にいるときは、その後ろに出るので見えない。初回起動の途中に届いたら、ホームに着いてから出す

#### 5.1.7 プラットフォームのアイコンと並び

- YouTube・X・Instagram・ツイキャス・Twitch のアイコンは、各社の公式のロゴを、形と色を変えずに出す（各社のブランドの決まりのため）。X は、明るい画面では黒、暗い画面では白のロゴにする（背景に溶けないように）。ツイキャスは、公式のアプリアイコン（ツイキャス・ライブ）を出す。プラットフォームのない予定だけ、追星で描いた形にする。
- どのロゴも、同じ大きさを指定したら、見た目の大きさがそろうようにする（余白の割合はコードが正）。
- 複数のロゴは、重ねずに並べる。
- SNS を並べるときは、どの画面でも、YouTube・X・Instagram・ツイキャス・Twitch の順にする（チップ・行・カード・注記の文言の並びを含む）。準備中の SNS（TikTok・ニコニコ。v1.0.0 は Instagram も先頭に。機能仕様書 4.6.2）は、そのあとに置く。プラットフォームのない予定（イベント）を並べるときは、最後に置く。

#### 5.1.8 タブの受け持ち

タブは、アプリの中の場所として扱う。画面は、どのタブから押しても、受け持ちのタブで開く。

| タブ | 役割 | 受け持つ画面 |
| --- | --- | --- |
| ホーム | 全体の入り口。推しの今を、まとめて見る | ホーム、イベント一覧（ホームから開いたもの） |
| スケジュール | 予定を見る | タイムスケジュール、月のカレンダー（タイムスケジュールから開いたもの） |
| 設定 | 設定を変える | 設定と、そこから開く画面 |
| 推し | 発信者を見る（推していない発信者も含む） | 推しリスト、推しを探す、発信者ページ、月のカレンダー・イベント一覧（発信者ページから開いたもの） |
| 発信者 | 発信者として、自分の発信者を整える（発信者だけ） | 発信者メニューと、そこから開く画面（自分の発信者ページも含む） |

- ほかのタブから開く　→　受け持ちのタブへ移り、そのタブを最初の画面まで戻してから開く。積み重ねは、いつも「最初の画面 → 開いた画面」にする（前に開いていた画面は閉じる）。いちばん上に同じ発信者のページが出ていれば、何もしない（発信者ページだけ。いろいろな入口から開けて、同じページを重ねやすいため。ほかの画面は、同じものでも重ねる）
- 同じタブの中で開く　→　いまの画面の上に重ねる（推しを探す → 発信者ページ など）
- 移るときの見え方　→　タブは一瞬で切り替え、開く画面だけを横から出す。移った先のタブの最初の画面を、途中で見せない。下部ナビの選択は、移った先のタブに変わる
- 戻る（右へ払う・端末の戻る・戻るのボタン）　→　移った先のタブの中で戻る。元のタブには戻らない。元のタブは、開いていた画面とスクロールの位置をそのまま残すので、下部ナビで戻れる
- 発信者ページから開く月のカレンダーとイベント一覧は、発信者ページの一部として、推しのタブの中で開く。スケジュールのタブへは移らない（タイムスケジュールの絞り込みを変えないため）
- イベントの詳細は、どのタブにも受け持たせず、押したタブの中で、いまの画面の上に重ねる
- タブの上に重ねる画面（投稿ビューア、シート、ダイアログ）は、どのタブにも属さない。いまのタブの上に出す。そこから発信者ページを開くときは、重ねた画面を閉じて、推しのタブに開く
- 発信者メニューのプロフィールカードから開く自分の発信者ページは、例外として、発信者のタブの中で開く（推しのタブへは移らない）。そこから開く月のカレンダーとイベント一覧も、発信者のタブの中で開く。配信中でも、ページの中では流さない（ほかの発信者ページと同じく、固定ビューアで流す）
- 通知（5.1.6）と固定ビューア（[画面定義書（ファン向け）](screen-design-fan.md) 2.4.3）から開く発信者ページも、推しのタブに開く
- 推しを探す（おすすめ・検索）と推しリストは、v1.0.0 では推しのタブの中に置く（2026-11-09）。独立したタブに分けるかは、公開後に使われ方を見て決める。分けたら、推していない発信者のページを開くタブを決め直す

#### 5.1.9 配色

画面の枠は、白と黒の中立の色（Instagram・YouTube・X と同じ）に寄せ、色は中身（サムネイル・SNS のアイコン）に任せる。黄みのある生成りは、黄色く見えすぎたのでやめた（2026-11-09 本人）。追星らしさは、キャラクターの4色を、決めた少ない場所だけに差して出す（決定事項 5。2026-11-09）。値はコード（`app/lib/ui/core/themes/app_colors.dart`）が正。Figma の変数「追星の色」と画面は、この配色に合わせてある（figma-check.md 5章）。

| 役割 | ライト | ダーク |
| --- | --- | --- |
| 背景 | 白 `#FFFFFF`（スプラッシュと同じ） | `#0F0F0F`（YouTube と同じ。スプラッシュと同じ） |
| 面・区切り | 中立の灰色（面 `#F2F2F2`、薄い塗り `#EDEDED`、区切り `#E5E5E5`、枠線 `#CCCCCC`） | 中立の暗い灰色（面 `#212121`、薄い塗り `#303030`、区切り `#272727`、枠線 `#3F3F3F`） |
| 文字 | ほぼ黒 `#0F0F0F`、補助 `#606060`・`#666666` | 黄みのない白 `#F1F1F1`、補助 `#C8C8C8`・`#AAAAAA` |
| 主要色（ボタン・選ばれている印・スイッチ） | ほぼ黒 `#0F0F0F`。上の文字は白 | 白 `#F1F1F1`。上の文字は背景の色 |
| リンク | キャラクターの青を濃くした `#0A6FD6` | `#5AA9FF`（投稿ビューアの黒の背景でも使う） |

- 文字と背景は、WCAG AA（本文 4.5:1）を満たす。いちばん低いのは、ライトの補助の文字 `#666666` を区切りの色 `#E5E5E5` に置いたときの 4.56:1。
- アプリのアイコンの絵の中の生成りは変えない。
- 差し色は、紺色（前の主要色。ライト `#525CA5`、ダーク `#A0A7E8`）と、キャラクターの緑 `#50A22F`・青 `#017EFB`・赤 `#F61E15`（ホームのロゴの絵から取った）。使うのは、次の場所だけにする。黄は使わない（2026-11-09 本人）。
  - 新着のある推しの輪：紺・緑・青のグラデーション。赤は配信中の輪と取り違えるので使わない。
  - 「NEW」の印：紺の塗りに、ライトは白、ダークはほぼ黒の文字（どちらも 4.5:1 以上）。
  - 何もないときの絵（5.1.3）：紺の薄い輪と、紺の薄い塗りの丸に紺のアイコン、緑・青・赤の粒。
  - スナックバーの操作の文字：紺の明るい版（ライト `#A0A7E8`、ダーク `#B8BEF0`）。
  - これからの予定があるときのカレンダーのボタン：紺の薄い塗りに紺のアイコン（ライト `#E1E0F9` / `#525CA5`、ダーク `#35344A` / `#A0A7E8`）。
  - 画面モードのシートの見本の、ヘッダーの丸：紺。
- 下部ナビの選んだタブは、塗りのアイコンと後ろの薄い灰色の楕円で見分ける（印の点は置かない。2026-11-09 本人）。
- 意味のある色は、役割をそのまま保つ。配信中の赤（`#E53935` とピンク）は変えない（キャラクターの赤に寄せると、配信中の印として目立ちすぎるため）。確認済みの緑はキャラクターの緑の系統（ライト `#2F7A1F` / `#E4F1DA`）、今の時刻の線と土曜の文字はキャラクターの青の系統（ライト `#0A6FD6`、ダーク `#5AA9FF`）にした。
- SNS の色（予定のブロック・投稿元のバッジ）と、Apple・Google のログインのボタンは、各社の決まりのまま（決定事項 5）。
