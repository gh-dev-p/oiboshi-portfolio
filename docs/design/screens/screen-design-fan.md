## 1. 本書の目的・範囲

- 各画面の詳細は、画面名の見出しごとに、役割・入口・構成要素・入力・遷移・異常系を書く。
- 全画面に共通するルール（下部ナビ、ヘッダー、状態表示、一覧の読み直し）は、[画面定義書 5.1](screen-design.md) を参照する。
- 遷移先の画面は、どのタブから押しても、受け持ちのタブで開く（発信者ページは推しのタブ。[画面定義書 5.1.8](screen-design.md)）。
- 振る舞いの決まり（何を流すか・いつ止めるかなど）は、機能仕様書が正。本書は、画面に何が出て、押すとどうなるかを書き、決まりは機能仕様書の節を参照する。
- 色・寸法などの見た目は、Figma が正。
- 画面IDは振らない。画面は名前で呼ぶ。

## 2. 各画面の詳細設計

### 2.1 初回起動

#### 2.1.1 ウェルカム

| 項目 | 内容 |
| --- | --- |
| 役割 | 初回起動で最初に出す |
| 関連機能 | 匿名サインイン、利用規約とプライバシーポリシーへの同意（機能仕様書 4.1.1・4.1.2） |
| 入口 | 初回起動（初回起動を済ませていないとき） |

<kbd>構成要素</kbd>

- イラストと、アプリ名「追星」、キャッチコピー（「推しの配信・投稿・予定が、ひとつに集まります。」）
- 「はじめる」ボタン。押したあと、推しを選ぶから戻るまでは、押せない
- 「発信者の方はこちら」テキストボタン
- 同意の文（「「はじめる」を押すと、利用規約とプライバシーポリシーに同意したものとします。」）。「利用規約」「プライバシーポリシー」はリンクにする
- ヘッダーと下部ナビは出さない

<kbd>遷移</kbd>

- 「はじめる」　→　匿名でサインインし、推しを選ぶへ。サインインに失敗しても進み、推しを選ぶの「読み込めない」で知らせる
  - 共有のページから入れた人（クリップボードに共有のリンクがある）には、推しを選ぶの前に、その発信者の発信者ページ（2.4.1）を、いつもの形で重ねて出す。戻ると推しを選ぶへ（届ける・広める仕様書 4.3.4）。クリップボードを読むとき、iOS の「ペーストを許可」の確認が出る。確かめるのは端末で1回だけ
- 「発信者の方はこちら」　→　発信者として登録へ
- 「利用規約」「プライバシーポリシー」　→　公開ページを開く

<kbd>異常系</kbd>

- 公開ページを開けない　→　スナックバー「ページを開けませんでした」

#### 2.1.2 推しを選ぶ

| 項目 | 内容 |
| --- | --- |
| 役割 | 最初にフォローする推しを選ぶ |
| 関連機能 | フォロー、推しの検索・おすすめ（機能仕様書 4.2.1・4.2.2） |
| 入口 | ウェルカムの「はじめる」 |

<kbd>構成要素</kbd>

- 見出し「推しをフォローしましょう」と説明（「フォローした推しの、配信・投稿・予定が、ホームに集まります。」）
- 検索フィールド（プレースホルダ「名前やIDで探す」）
- 発信者の一覧（20人まで）。言葉が空のときは、おすすめ（機能仕様書 4.2.2.2）。おすすめが0人なら、一覧には何も出さない。各行に、アイコン（配信中なら、リングで印を出す）、名前、ひとこと（プロフィール文の1行目）、フォロー／フォロー中のボタン。フォローしても、行は消さない。行そのものは押せない
- 下部のバーに、「次へ」と「あとで」。フォロー中が1人以上なら、「次へ」に人数を出す（「次へ（{人数}人をフォロー中）」）
- ヘッダーと下部ナビは出さない

<kbd>入力項目・バリデーション</kbd>

- 検索：名前・ID・SNS のアカウントで探す（機能仕様書 4.2.2）。入力が止まってから探し、結果が届くまでは、前の一覧を出しておく。

<kbd>遷移</kbd>

- 「次へ」「あとで」　→　通知の説明へ
- 端末の戻る操作　→　ウェルカムへ

<kbd>異常系</kbd>

- 読み込み中　→　スケルトン
- 読み込めない（サインインの失敗を含む）　→　状態表示（読み込めない）。「もう一度試す」で、サインインからやり直す
- フォローを変えられない　→　スナックバー「フォローを変えられませんでした」
- 検索に合う発信者がいない　→　一覧の場所に、推しを探す（結果なし。2.3.3）と同じ状態表示

#### 2.1.3 通知の説明

| 項目 | 内容 |
| --- | --- |
| 役割 | 通知の許可を求める理由を説明してから、OS の許可の画面を出す |
| 関連機能 | 配信開始の通知（機能仕様書 4.3.3） |
| 入口 | 推しを選ぶの「次へ」「あとで」 |

<kbd>構成要素</kbd>

- 通知の見本カード（アプリアイコン、「星野ミナトが配信を始めました」、配信のタイトル（「【Apex】プラチナ帯ソロランク耐久！」））
- ベルのイラスト
- 見出し「配信が始まったら、お知らせします」
- 説明（「推しが配信を始めたときに、通知でお知らせします。あとから、設定で変えられます。」）
- 「通知をオンにする」ボタン
- 「いまはしない」テキストボタン
- ヘッダーと下部ナビは出さない

<kbd>遷移</kbd>

- 「通知をオンにする」　→　OS の許可の画面を出し、結果にかかわらず、初回起動を済ませて、ホームへ。許可されたら、端末を通知の送り先に登録する（機能仕様書 4.3.3）
- 「いまはしない」　→　初回起動を済ませて、ホームへ
- 端末の戻る操作　→　推しを選ぶへ

<kbd>異常系</kbd>

- 初回起動を済ませた印を、端末に保存できない　→　知らせずに、そのままホームへ進む（次に開いたとき、初回起動をもう一度出すだけで済むため）

#### 2.1.4 起動できない

| 項目 | 内容 |
| --- | --- |
| 役割 | サーバーへの接続の準備ができず、アプリを始められないことを知らせる |
| 関連機能 | 起動 |
| 入口 | 起動のときに、サーバーへの接続の準備（Supabase の初期化）に失敗した、または10秒で終わらなかったとき。端末の保存領域の読み込みに失敗したとき。通知の準備（Firebase の初期化）の失敗では出さない（通知だけを止めて起動する） |

<kbd>構成要素</kbd>

- 見出し「起動できませんでした」と、その下に、エラーの内容
- ボタンは置かない（アプリを起動し直す）
- 文言は、端末の言語で出す

#### 2.1.5 スプラッシュ

| 項目 | 内容 |
| --- | --- |
| 役割 | アプリを開いてから、最初の画面を出すまでのあいだに出す |
| 関連機能 | 起動 |
| 入口 | 起動のたび（iOS の起動の画面。起動の準備（2.1.4 の入口に書いたもの）が終わるまで出す） |

<kbd>構成要素</kbd>

- 画面の真ん中に、追星のロゴ（星のキャラクター4体と手書きの「追星」。ホームのヘッダーのロゴ（2.2.1）と同じ絵）。幅は 340（大きさはコードが正）。暗い画面では、線と手書きの文字・小さな星を白にしたロゴを出す（2026-11-09 本人）
- 絵の差し替えと作り直しの手順は、`app/ios/Runner/Assets.xcassets/LaunchImage.imageset/README.md` に書く（調整は本人がやる）
- 背景は、アプリの画面の背景と同じ。明るい画面では白（`#FFFFFF`）、暗い画面では `#0F0F0F`（画面定義書 5.1.9）。端末の外観の設定に従う（アプリの中の表示の設定は、まだ読めないため）
- 動きは付けない（iOS の起動の画面は、動かない1枚の絵のため）。Flutter の側で、別の起動の画面は出さない

### 2.2 ホーム

#### 2.2.1 ホーム

| 項目 | 内容 |
| --- | --- |
| 役割 | 推しの更新を、1画面で見渡す。全体タイムラインを兼ねる |
| 関連機能 | 新着（機能仕様書 4.2.3）、ホームの埋め込みビューア（4.3.4）、予定の表示（4.5.3）、投稿（4.4） |
| 入口 | 下部ナビのホーム、初回起動の完了、起動（初回起動を済ませているとき） |

<kbd>構成要素</kbd>

- ヘッダー：中央に、追星のロゴ（星のキャラクター4体と手書きの「追星」。背景は透明）。ロゴは小さめ（高さ 28）にし、ヘッダーの高さは、ロゴに替える前（文字の「追星」）と同じ 48 のままにする（スケジュールのタブとそろう。2026-11-09 本人。大きさはコードが正）。暗い画面では、線と手書きの文字・小さな星を白にしたロゴを出す（キャラクターは変えない。2026-11-09 本人）。読み上げは「追星」。固定ビューア（2.4.3）を出している間は、ヘッダーを出さない
- 推しレーン：丸いアイコンを横に並べ、横にスクロールする。名前を下に出す。見出しと「すべて見る」は出さない
  - 埋め込みビューアで流している推し（固定ビューアで配信を流している間は、その推し）は、赤いリングと「LIVE」の印。ほかの配信中の推しは、灰色の細いリングと「LIVE」の印。固定ビューアで投稿の動画やランダム再生を流している間は、どの推しにも赤いリングを付けない
  - 新着あり（機能仕様書 4.2.3）は、灰色の細いリングと「NEW」の印。それ以外は、灰色の細いリングだけ
  - 並びは、配信中、新着あり、それ以外の順。同じ中では、フォローした順
- 埋め込みビューア：推しレーンの下に、配信中の推しの映像を流す。配信中の推しがいないとき、固定ビューアが出ている間は出さない。流す条件・切り替えの順・音は、機能仕様書 4.3.4 を参照する
  - 映像は、画面の幅いっぱいの 16:9。映像の上には、ツイキャスの音の印のほか、何も重ねない（YouTube の規約）
  - 映像の下の帯に、左から「LIVE」と配信元を1つにした印（配信元の色とロゴ）、推しのアイコン、真ん中に切り替えの矢印「‹」「›」と何人目かの点（配信中の推しが2人以上のとき）、右端に固定ビューアのボタン（下部ナビのスイッチと同じアイコン）。帯の寸法・間隔は Figma が正で、固定ビューアの帯も同じ並びにする
  - 流さないときは、サムネイルを出す
- 「次の予定」：見出しつきの面に、今日のこれからの予定を時刻順に縦に並べる。見出しは「次の予定」のまま（言葉として、わくわくするため）。明日より先の予定、始まった予定、終日の予定、イベントは出さない。1件もなくても面は出し、「今日はこれからの予定はありません」と出す
  - 各行に、予定の開始時刻、推しのアイコン、タイトルと名前、プラットフォームのアイコンを出す（今日の予定だけなので、日付は出さない）。推しが配信中でも、左端は予定の開始時刻にする（これからの予定だけを並べるため）
  - 出す件数は2件。3件以上あるときは、見出しの右に「ほか {N} 件」と右向きの矢印を出す
- 「イベント」：「次の予定」の下に、見出しつきの面で、推しのこれからのイベント（1年以内）を日付順に縦に並べる。イベントは、発信者がイベントの登録で作る、プラットフォームを持たない予定（会場で行うイベント、チケットのあるイベント）。開催中のもの（終了時刻の前のもの。終了時刻がなければ開始の前のもの。終日なら、その日のあいだ）は出し、終わったものは出さない。1件もなくても面は出し、「これからのイベントはありません」と出す
  - 各行に、左に日付のブロック（月と日。イベント一覧と同じ）、右にタイトルと「{曜日} {開始の時刻}・{会場}」（終日は時刻の代わりに「終日」。イベントの公演で時刻が決まっていなければ「時刻未定」。会場がなければ「{曜日} {開始の時刻}」）。その下に、推しのアイコン（小）と名前
  - 出す件数は2件。3件以上あるときは、見出しの右に「ほか {N} 件」と右向きの矢印を出す
- 全体タイムライン：推しの投稿を、日時順に混ぜて縦に並べる。SNS を問わず、同じ枠で出す（統一感を出す）。配信中の YouTube の配信枠は出さない（埋め込みビューアで見る。機能仕様書 4.3.4）
  - 上から順に、投稿者の行、本文、画像、数
  - 投稿者の行：アイコン、名前、プラットフォームのアイコン（スケジュールと同じもの）、投稿からの時間（「たった今」「{n}分前」「{n}時間前」「{n}日前」。30日より前は日付）
  - 本文：YouTube はタイトル（なければ、投稿の種類（「動画」「ショート」など））、Instagram はキャプション、X は本文。長い本文は、途中で切る。本文の URL はリンクにする（長い URL は、`https://` などを省き、途中で切る）
  - 画像：あれば出す。縦横比は、SNS と投稿の種類に合わせる。Instagram の動画（リール）と X の動画は、動画のマークを出す
  - 数：いいね数、コメント数、再生回数を、この順に出す。SNS が出さない数は出さない（YouTube は再生回数だけ。X は数を出さない）。Instagram で、いいね数が隠されていれば、アイコンだけ出す
  - X の投稿は、ほかの SNS と同じ枠・同じ並びで出し、X の表示の決まりで外せないものを足す。投稿者の行は、推しのアイコンと2段（1段目：名前／2段目：投稿からの時間 · Xで見る）にし、右上に「X の投稿者の行」を出す。本文の @ユーザー名と #ハッシュタグは、リンクにする。いいね数・返信数は、押せるアイコンを出せないので、出さない（代わりに「Xで見る」）
  - X の投稿者の行：右上に、左から2段（1段目：X での表示名／2段目：「@{X のユーザー名}」）、X でのプロフィール画像、X のロゴ（右の端）を並べる。画像は X のロゴと同じ大きさにする。2段は、灰色の小さい字（10pt、1段 11）で左をそろえ、画像・ロゴの高さは2段の文字の高さ（22）にそろえて、文字がはみ出さないようにする。2段の文字の欄の幅は、画像の幅の2倍（44）までにし、入りきらないときは、表示名と @ユーザー名の右を「…」で切る。追星の発信者のものではなく、いつも X のものを出す（追星の発信者の名前・アイコンは変えない）。X のプロフィールをまだ取れていない間は、表示名の代わりに「@{ユーザー名}」（`creator_accounts.account`）を出し、アイコンは仮の人の形にする
  - 最新の50件を出し、下までスクロールすると、50件ずつ続きを読む。過去90日まで出す。続きを読んでいるあいだは、下に小さな読み込み中の印を出す。続きの読み込みに失敗したら、印を止めて、下に「読み込めませんでした」と「再試行」のボタンを出す。押すと、続きを読み直す
  - 読み切ったら、印を出さず、末尾に「過去90日ぶんを、すべて表示しました」を出す。投稿が1件もなければ「まだ投稿がありません」
- 下部ナビを出す

<kbd>遷移</kbd>

- 推しのアイコン（赤いリングの推し）　→　発信者ページ（2.4.1）へ
- 推しのアイコン（ほかの配信中の推し）　→　埋め込みビューアを、その推しに切り替える（固定ビューアで流していれば、固定ビューアのまま切り替える）
- 推しのアイコン（配信中でない）　→　発信者ページへ
- 埋め込みビューアの映像　→　プレイヤーを操作する（発信者ページには移らない）。ツイキャスは、ミュートを切り替える
- 埋め込みビューアの帯の推しのアイコン　→　その推しの発信者ページ（2.4.1）へ
- 埋め込みビューアの帯の「LIVE」と配信元の印　→　配信ページを外部で開く
- 埋め込みビューアの帯の固定ビューアのボタン　→　その配信を固定ビューア（2.4.3）で流す（下部ナビのスイッチも入れる）
- 埋め込みビューアの帯を横に払う・矢印　→　前後の配信中の推しへ（周回する）。払うと、映像は指について横に動く。切り替わったら、軽く振動させる。映像の上では払えない
- 「次の予定」の行　→　発信者ページへ
- 「イベント」の行　→　ホームのタブの中で、イベントの詳細（[画面定義書（スケジュール）](screen-design-schedule.md) 2.3.2）へ
- 「次の予定」の「ほか {N} 件」　→　スケジュールのタブ（24時間のタイムスケジュール）へ

- 引き下げ　→　読み直す
- 下部ナビのホーム（ホームの最初の画面を開いているとき）、ステータスバーを押す（iOS）　→　いちばん上までスクロールする

<kbd>構成要素</kbd>

- 推しの行。アイコン、名前、副文、右に「フォロー中」のボタン
  - アイコンは、ホームの推しレーンと同じリングと印（「LIVE」「NEW」）
  - 副文は、上から順に、当てはまる最初のものを出す
    - 配信中　→　「配信中：{タイトル}」
    - 次の予定がある（1年以内。始まった予定と終日の予定を除く。イベントを含む）　→　「{日時} {タイトル}」（日時は「今日 21:00」「明日 12:00」「10/16 22:00」の形。タイトルがなければ「配信」）
    - どれでもない　→　「予定はありません」
- 下部ナビを出す

- 検索：名前・ID・確認済みの SNS のアカウントで、一覧を絞り込む。先頭に続く `@` は無視する。
- 並び：配信中を先に、残りはフォローした順。

<kbd>遷移</kbd>

- 行・推しのアイコン　→　発信者ページへ。配信中の推しでも、固定ビューアで流しているものは変えない（その配信を流すときは、開いた発信者ページの「固定ビューアで見る」で流す。2.4.1）
- 「フォロー中」　→　確認なしで、フォローを解除する。読み直したあとに、行を消す
- ヘッダーのアイコン　→　推しを探すへ
- 引き下げ　→　読み直す。推しが0人のとき、検索に合う推しがいないとき、読み込めないときも、引き下げで読み直せる

<kbd>異常系</kbd>

- 読み込み中　→　スケルトン
- フォロー中の推しが0人　→　状態表示（イラスト、「推しがいません」、説明「推しをフォローすると、ここに並びます。」、「推しを探す」ボタン）。「推しを探す」で、推しを探すへ
- 検索に合う推しがいない　→　件数と並びは残し、一覧の場所に状態表示（イラスト、「見つかりませんでした」、説明「「{入力した言葉}」に合う推しは、フォロー中にいません。」）。ボタンは置かない
- 初めて読み込めない　→　状態表示（読み込めない）。「もう一度試す」で、サインインからやり直す
- 更新に失敗（表示済み）　→　内容を残したまま、スナックバー「更新できませんでした」と「再試行」
- フォローを解除できない　→　スナックバー「フォローを解除できませんでした」

#### 2.3.4 追いたい

| 項目 | 内容 |
| --- | --- |
| 役割 | 追星にまだいない人を、SNS の URL か ID で申告する。自分が押した追いたいを見て、取り消す |
| 関連機能 | 追いたい（[機能仕様書（届ける・広める）](../specs/functional-spec-reach.md) 4.5.1） |
| 入口 | 推しを探すのヘッダーの追いたいのアイコン、推しを探す（結果なし）の「追いたいで申告する」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「追いたい」
- 説明（「追星にまだいない人を、SNS の URL か ID で申告できます。その人が追星に来たら、お知らせして自動でフォローします。」）
- 入力欄「URL か ID」（プレースホルダ「https://x.com/… や @ID」）
- 「SNS（ID だけのときに選ぶ）」と、この版で出す SNS のチップ（並びは 5.1.7）。URL から SNS が分かれば、そのチップを選んだ形で出す。同じチップをもう一度押すと、選ぶのをやめる
- 読み取れたら「申告する ID」と、SNS のアイコンと ID（YouTube はハンドルかチャンネル ID のまま、ほかは `@` を付ける）
- ボタン「追いたい」（入力が空なら押せない）
- 注記（「追星が持つのは、SNS と ID と押した人数だけです。誰が押したかは、ほかの人に見せません。」）
- 見出し「あなたの追いたい」と、自分が押した追いたいの一覧（新しい順）。各行：SNS のアイコン（発信者のアイコンと同じ丸に入れる。他人の名前やアイコンは出さない）、ID、「本人確認なし」の印、押した人数（「{人数}人が追いたい」。自分を含む。丸めない）、「取り消す」
- 一覧が空なら「まだ追いたいはありません」
- 下部ナビを出す

<kbd>入力項目・バリデーション</kbd>

- URL か ID：読み方は機能仕様書（届ける・広める）4.5.1。この版で出さない SNS（Instagram・ツイキャス）は読めないものとして扱う

<kbd>遷移</kbd>

- 「追いたい」　→　押せたら、スナックバー「追いたいにしました」。入力と SNS の選択を空に戻し、一覧を読み直す
- 「追いたい」で、確認済みのアカウントだった　→　スナックバー「この人は、もう追星にいます」と、その発信者のページ（推しのタブの中）
- 「取り消す」　→　一覧から外す

<kbd>異常系</kbd>

- URL・ID が読めない　→　スナックバー「この形の URL は読めません」
- ID だけで SNS を選んでいない　→　スナックバー「ID だけのときは、SNS を選んでください」
- 1日の上限を超えた　→　スナックバー「今日はこれ以上申告できません」
- 送れない　→　スナックバー「申告できませんでした」
- 取り消せない　→　一覧に戻し、スナックバー「取り消せませんでした」
- 一覧を読み込み中　→　くるくる。読み込めない　→　「読み込めませんでした」と「もう一度試す」

### 2.4 発信者ページ

#### 2.4.1 発信者ページ

| 項目 | 内容 |
| --- | --- |
| 役割 | 発信者の情報、次の予定、投稿を見る |
| 関連機能 | フォロー（機能仕様書 4.2.1）、新着（4.2.3）、ファンのカバー画像（4.2.4）、フォロワー数（4.2.5）、発信者を表示しない（4.2.6）、通報（4.2.7）、配信の再生（4.3.2）、配信開始の通知（4.3.3）、固定ビューア（4.3.5）、予定の表示（4.5.3）、リンク集（届ける・広める仕様書 4.6.2） |
| 入口 | 推しの名前・アイコンを出す画面のほとんど（推しレーン、推しリスト、推しを探す、予定の詳細、ホームの「次の予定」の行、埋め込みビューア・固定ビューアの帯の推しのアイコン、スケジュールの列の見出し、イベントの詳細の発信者の行、タイムラインと投稿ビューアの投稿者のアイコン・名前）、配信開始の通知（画面定義書 5.1.6）、発信者メニューの「自分のページ」（オーナーだけ） |

<kbd>構成要素</kbd>

- ヘッダーは置かない。カバー画像を上端に出す。カバーは横3：縦1（画面の幅の1/3の高さ）で出し、上のステータスバーの分は、その上に足す。はみ出す部分は切る
  - フォロー中なら、カバーを変えるカメラのアイコンを置く。押すと、「写真を選ぶ」と、自分の写真があるときは「推しが設定したカバーに戻す」を出す
  - 自分の写真があるときは、カバーに「表」（推しのカバー）と「裏」（自分の写真）がある。カバーの隅に、裏返せることを示す小さな印を出す。読み上げの名前は「カバーを裏返す」
- カバーの右上に、メニューのボタン（「…」）。押すと「リンクを共有」「通報する」「この発信者を表示しない」を出す。自分がオーナーの発信者（オーナーかを読み込んでいる間も）には、「リンクを共有」だけを出す（読めなければ全部出す）。
- アイコン。配信中は、赤いリングと「LIVE」の印にする（ホームの推しレーン（2.2.1）の印と同じ形）。配信中でも、ページの見た目はほかに変えない（2026-11-19 本人）
- 名前の行：名前（24pt の太字、行の高さ 32。長ければ折り返す）と、右に2つのボタン。フォローしていないときは「フォロー」のボタン、フォロー中はベルだけの丸いボタン（大きさは月のカレンダーへのボタンと同じ 36。通知オンは塗ったベル、通知オフは斜線の入ったベル）。その右に、月のカレンダーへのボタン（次の予定かイベントがあれば、印をつける）
- ID（「@{ID}」。14pt・中くらいの太さ・薄い色、行の高さ 20）
- 「固定ビューアで見る」のボタン（主色の塗りのボタン）：ID の下に出す。配信中で、固定ビューアでいまその配信を流していないとき（固定ビューアを閉じている・別の配信や動画を流している・コントローラーで止めている）だけ出す。その配信を流している間は出さない（2026-11-19 本人）
- プロフィール文（14pt、行の高さ 20）。1行目だけを出し、2行目からは折りたたむ。1行に収まらないとき、または改行があるときは、1行目の終わりを「…」にして、下に「もっと見る」を出す。開くと全文と「閉じる」を出す。「もっと見る」「閉じる」は 14pt・中くらいの太さ・薄い色
  - 名前・ID・プロフィール文の大きさ・太さ・行の高さは、YouTube の iOS アプリのチャンネルのページに合わせる（2026-11-19 本人）。色は今のまま（ID と「もっと見る」は薄い色、プロフィール文は濃い色）
- 合計フォロワー数（数を上に 20pt の太字で大きく、その下に「合計フォロワー」を 13pt の薄い色で小さく、縦に積む。Instagram・X のプロフィールと同じ形。2026-11-19 本人）と、その下にSNS ごとの内訳（チップ。押すと、その SNS を開く。確認済みのアカウントがない SNS（確認が外れてから、数が消えるまでの間）のチップは、押せない）。数の書き方と合計の切り捨ては、機能仕様書 4.2.5。フォロワー数が1つも取れていなければ、出さない
- リンク集（届ける・広める仕様書 4.6.2）：つないだ SNS（合計フォロワー数と SNS のチップ）の下に、リンクを1件1つの横いっぱいのボタンで、オーナーが決めた順に縦に並べる。ボタンには、左に行き先のサービスの公式アイコン（YouTube・X・Instagram・Twitch。それ以外はふつうのリンクの印。届ける・広める仕様書 4.6.7）、真ん中に題名を出す。追星に誘うリンク（届ける・広める仕様書 4.6.6）は出さない。つないだ SNS のアカウントのページを指すリンク（自動で入れた SNS のリンク（4.6.5）を含む）は出さない。SNS ごとのフォロワー数の所（押すとその SNS を開く）で足りるため（2026-11-19 本人）。出すリンクが1件もなければ、何も出さない
- 「次の予定」のカード（1年以内。終日の予定とイベントを除く。イベントは、下の「イベント」に出す）。見出しは「次の予定 ・ {あとどれくらいか}」（「開始済み」「まもなく」（1時間を切ったら）「あと{n}時間」（同じ日）「明日」「{n}日後」）。プラットフォームのアイコン、タイトル（なければ「配信」）と、「{プラットフォーム名} ・ {日付（曜日つき）} {時刻}〜」
- 「イベント」：「次の予定」のカードの下に、見出しつきの面で、この発信者のこれからのイベントを日付順に縦に並べる。対象・行の出し方・件数（2件と「ほか {N} 件」）は、ホームの「イベント」（2.2.1）と同じ。アイコンと名前は出さない（この発信者のページのため）。1件もなくても面は出し、「これからのイベントはありません」と出す（ファンが、ないことを確かめられるように）
- 投稿のタイムライン。日時順に混ぜて、残してある投稿をすべて出す。カードは、ホームの全体タイムラインと同じ。フォロー中で、新着（機能仕様書 4.2.3）とそれより前の投稿の両方があるときは、その間に「ここまで新着」の区切りを出す。投稿がなければ「まだ投稿がありません」
- 下部ナビ（画面定義書 5.1.1）

<kbd>入力項目・バリデーション</kbd>

- カバーを変える：端末の写真から選ぶ。自分にだけ見える。選んだ直後は、裏（自分の写真）を出す（機能仕様書 4.2.4）。

<kbd>遷移</kbd>

- フォロー中の発信者のページを開く　→　見たことを記録する（新着の基準を更新する）
- ページを開く（配信中の発信者でも）　→　固定ビューアで流しているものは変えない
- 「フォロー」　→　フォローする（機能仕様書 4.2.1）
- ベル　→　シートを出す。「通知をオンにする」か「通知をオフにする」（今の状態の逆）と、「フォローをやめる」を選ぶ
  - 「通知をオンにする」「通知をオフにする」　→　その推しの通知のオン・オフを切り替える（配信開始の通知と予定の事前通知の両方。`follows.notify`）。失敗したら、スナックバー「通知の設定を変えられませんでした」
  - 「フォローをやめる」　→　確認なしで、フォローを解除する。失敗したら、スナックバー「フォローを変えられませんでした」
- カバー（自分の写真があるとき）　→　縦の軸で裏返るアニメーションで、表と裏を切り替える。どちらを出しているかは、推しごとに覚える
- 「推しが設定したカバーに戻す」　→　自分の写真を消し、推しのカバーに戻す
- 月のカレンダーへのボタン　→　月のカレンダーへ（この発信者の予定）
- 「次の予定」のカード　→　予定の詳細を出す
- 「イベント」の行　→　発信者ページと同じタブの中で（ふつうは推しのタブ。自分のページは発信者のタブ）、イベントの詳細（[画面定義書（スケジュール）](screen-design-schedule.md) 2.3.2。発信者の行は押せない）へ
- 「イベント」の「ほか {N} 件」　→　発信者ページと同じタブの中で、イベント一覧（この発信者。[画面定義書（スケジュール）](screen-design-schedule.md) 2.3.1）へ
- SNS のチップ　→　その SNS を、外部で開く
- リンク集のボタン　→　確認のダイアログ（「外部のサイトを開きます」、題名、行き先のドメイン、「開く」「キャンセル」と、自分がオーナーの発信者でなければ「このリンクを通報する」）。「開く」で外部のページを開き、押された数を数える（オーナー自身は数えない）。「このリンクを通報する」で、通報（シート。2.6.1）を、そのリンクを対象に出す。`https://` で始まらないリンクは開かず、スナックバー「ページを開けませんでした」
- プロフィール文の「もっと見る」　→　全文を出す。「閉じる」　→　1行目だけに戻す
- プロフィール文・本文の URL　→　外部で開く
- 投稿、投稿者の行　→　投稿ビューアへ（その推しの投稿を、新しい順に前後へ移る）。X の投稿者の行と、投稿からの時間・「Xで見る」を押したときの動きは、ホームと同じ
- 引き下げ　→　読み直す
- アイコン　→　何もしない（配信中でも）
- 「固定ビューアで見る」　→　その配信を固定ビューア（2.4.3）で流す（下部ナビのスイッチも入れる。止めていたなら、流し直す）。ページは移らない
- 開いているあいだに配信が始まった　→　アイコンを「LIVE」の印にし、「固定ビューアで見る」を出す
- 開いているあいだに配信が終わった　→　「LIVE」の印と「固定ビューアで見る」を消す（知らせは出さない）
- 右へ払う　→　前の画面へ
- 「リンクを共有」　→　「リンクを共有」の画面（2.4.4）を重ねて開く
- 「通報する」　→　通報（シート。2.6.1）
- 「この発信者を表示しない」　→　確認のダイアログ（「{名前}を表示しないようにしますか？」「フォローを外し、検索やタイムラインにも出さなくなります。設定から元に戻せます。」、「表示しない」「キャンセル」）。「表示しない」で、前の画面に戻り、スナックバー「この発信者を表示しないようにしました」

<kbd>異常系</kbd>

- 読み込み中　→　スケルトン
- 初めて読み込めない（発信者が見つからないときを含む）　→　状態表示（読み込めない）
- 更新に失敗（表示済み）　→　内容を残したまま、スナックバー「更新できませんでした」と「再試行」
- フォローを変えられない　→　スナックバー「フォローを変えられませんでした」
- 通知を変えられない　→　スナックバー「通知の設定を変えられませんでした」
- カバーを変えられない　→　スナックバー「カバーを変えられませんでした」
- カバーのどちらの面を出しているかを覚えられない　→　知らせない
- 表示しないにできない　→　スナックバー「表示しないにできませんでした」

#### 2.4.2 配信中の発信者ページ

- 廃止した（2026-11-19 本人）。発信者が配信中のときに、発信者ページの見た目を切り替える作り（上部の映像と帯、小さなプロフィールと全表示の切り替え、コンパクトな投稿の行、帯で前後の配信中の推しのページに替える、ページの中のプレイヤーなど）を無くした。見た目の切り替えが、不具合のもとになっていたため。番号は、ほかの文書とコードから指しているので残す。
- 配信中でも、発信者ページ（2.4.1）をいつもの見た目で出す。配信は、ページの中では流さず、固定ビューア（2.4.3）で流す。発信者ページの「固定ビューアで見る」で、その配信を固定ビューアで流す。

#### 2.4.3 固定ビューア

| 項目 | 内容 |
| --- | --- |
| 役割 | 配信か推しの動画を流したまま、アプリの他の画面を操作する（ながら見） |
| 関連機能 | 固定ビューア（機能仕様書 4.3.5）、推しの動画のランダム再生（4.3.5.1） |
| 入口 | 下部ナビのスイッチ（画面定義書 5.1.1）、ホームの埋め込みビューア・投稿ビューアの固定ビューアのボタン、発信者ページの「固定ビューアで見る」（2.4.1）、投稿ビューアで左へ払う |

何を流すか・いつ切り替えるか・配信の終わりの扱いは、機能仕様書 4.3.5 を参照する。開いたときは、最後に流していたものの続きから流す（動画はその位置から、配信はまだ配信中なら。2026-11-18 本人）。

開いたときに出すか（下部ナビのスイッチの初めの状態）：推しが0人なら出さない（初めて開いたときの空のホームを邪魔しない）。推しが1人以上なら出す。0人から推しを足したときは、足した画面では何もせず、次にホームを開いたときに出す。ユーザーがスイッチで切ったら、開き直しても切ったまま。決まりは機能仕様書 4.3.5（2026-11-10 本人）。

<kbd>構成要素</kbd>

- 映像と、その下の帯。画面のいちばん上（ステータスバーの下）の、左右の真ん中に据え付け、どのタブの上にも出す。ドラッグでは動かさない。タブの画面は、固定ビューアの下から、すき間を空けずに始める（重ねない）
  - 出している間は、タブの画面に使える縦が狭くなるので、ヘッダーを減らす。ホームはヘッダーを出さない（2.2.1）。ほかの画面は、ヘッダーを固定せず、中身と一緒にスクロールして上に隠す（推しリスト 2.3.1、発信者メニュー・設定と、押して入る画面。決まりは [画面定義書 5.1.2](screen-design.md#512-ヘッダー)）。タイムスケジュールだけは、ヘッダーと週ストリップを固定したままにする（[画面定義書（スケジュール）](screen-design-schedule.md)）。発信者ページは、もともとヘッダーを固定しない（2.4.1。カバーも、ページと一緒にスクロールする）
- 映像の幅は、画面の幅いっぱい（最大 400。YouTube の規約の最小の大きさを満たすため）。配信は 16:9。投稿の動画は、種類で縦横比を決める（YouTube のショートと Instagram のリールは 9:16 で幅 200、YouTube の動画と X の動画は 16:9、Instagram の動画（リール以外）は正方形）
- 帯：並びはホームの埋め込みビューアの帯（2.2.1）と同じ決まり。閉じるボタンは置かない（下部ナビのスイッチで消す）。映像の上には何も重ねない（YouTube の規約）
  - 配信：左から「LIVE」と配信元の印、推しのアイコン、（2人以上のとき）切り替えの矢印と何人目かの点、右にランダム再生に切り替えるボタン（重なった動画のアイコン。2026-11-18 本人。シャッフルではなく「動画」だと分かるように）
  - ランダム再生：左から配信元（YouTube）のアイコン、推しのアイコン、前後の動画の矢印、右に配信に切り替えるボタン（配信中の推しがいるとき）
  - 投稿ビューアから入れた投稿の動画：左に配信元のアイコン、右に配信に切り替えるボタン（配信中の推しがいるとき）と、ランダム再生に切り替えるボタン
- 配信と YouTube の動画の映像は、プレイヤーをそのまま操作できる（ツイキャスは、右下のミュートの印）。Instagram・X の動画の映像は操作できない（押すと、投稿ビューアで開く）
- 投稿ビューア（2.5.1）を開いている間も、隠さずに流し続ける（投稿ビューアは、固定ビューアの下に出る）。投稿ビューアの動画は自動で流さず、ファンが押して流している間だけ、固定ビューアを一時停止する。止める・別の投稿に移る・閉じると、流し直す（機能仕様書 4.3.5。2026-11-19 本人）
- 流すものがないとき（スイッチを入れたのに、配信中の推しも流せる動画もない）：帯は出さず、配信の映像と同じ大きさの暗い枠に、再生の画面のアイコン、「配信や動画を投稿している推しを見つけよう」、「推しを探す」のボタンを出す

<kbd>遷移</kbd>

- 帯の推しのアイコン　→　発信者ページへ（推しのタブに開く。画面定義書 5.1.8）。固定ビューアは、そのまま流す
- 帯の「LIVE」と配信元の印　→　配信ページを外部で開く
- 帯の配信元のアイコン（投稿の動画）、Instagram・X の動画の映像　→　投稿ビューアでその投稿を、同じ位置から開く。ビューアを閉じると、固定ビューアは、ビューアで見ていた位置から続ける（別の投稿に移ってから閉じたときは、止めた位置から）。ビューアの下のアイコン・名前を押せるかは、固定ビューアに入れたときのビューアと同じ（2.5.1。ランダム再生では押せる）
- 配信の帯を横に払う・矢印　→　前後の配信中の推し（推しレーンと同じ順。周回する）の配信に切り替える
- ランダム再生の帯を横に払う・矢印　→　前後の動画に移る。前の動画がなければ、少し動いて戻る
- 帯を払っている間　→　映像が指について横に動く（帯は動かさない）。速く払うか、幅の 25% より多く動かすと決まり、足りなければ戻る。指の当たっているあたりだけ、帯の下にふくらみを出して指についてこさせ、離したら引っ込める。切り替わったら、軽く振動させる
- ランダム再生に切り替えるボタン　→　推しの動画のランダム再生を始め、スナックバー「動画シャッフルモードに切り替えました」
- 配信に切り替えるボタン　→　配信中の推しの配信を流し、スナックバー「配信モードに切り替えました」
- 「推しを探す」（流すものがないとき）　→　推しを探す（2.3.2）へ
- 投稿ビューアから入れた投稿の動画（YouTube）が最後まで流れた　→　ランダム再生に移る。Instagram・X の動画は、繰り返して流す（終わらない）
- 配信が終わったと分かった　→　スナックバー「配信が終わりました」を出し、次に流すものを流す。次がランダム再生なら、スナックバーは「配信が終わりました。動画シャッフルモードに切り替えました」
- そのほか、配信モードとランダム再生が切り替わった（投稿ビューアから入れた動画が終わってランダム再生に移った、など）　→　スナックバー「配信モードに切り替えました」「動画シャッフルモードに切り替えました」

<kbd>異常系</kbd>

- 映像を再生できない（配信）　→　映像の場所に印だけを出す
- ランダム再生の動画を再生できない　→　サムネイルに再生のマーク（2.5.1）を出し、次の動画に進む（機能仕様書 4.3.5.1）
- 投稿ビューアから入れた投稿の動画を再生できない　→　サムネイルに再生のマークを出す。次の動画には進まない。YouTube は、押すと元の SNS を外部で開く
- ランダム再生に切り替えたが、流せる動画がない　→　流しているものはそのままにして、スナックバー「流せる動画がありません」
- ランダム再生に切り替えたが、読めない　→　流しているものはそのままにして、スナックバー「読み込めませんでした」

#### 2.4.4 リンクを共有

| 項目 | 内容 |
| --- | --- |
| 役割 | 発信者の誘う用のリンク（`…/c/{ID}?invite=1`）と QR を出し、OS の共有シートで共有する。QR は画像にして保存・共有できる |
| 関連機能 | リンクの共有（届ける・広める仕様書 4.3.2）、QR（4.3.5） |
| 入口 | 発信者メニューのプロフィールカードの共有のボタン（「追星に誘う」）、発信者ページのメニュー（「…」）の「リンクを共有」（ファンも、自分の発信者のオーナーも） |

見た目は、本人の指示で Figma を飛ばし、今の画面（プラン・発信者メニュー）の部品にそろえた仮の決め（2026-11-16）。

どこから開いても、QR・リンクの行・共有するリンクは誘う用のリンクにする（2026-11-19 本人：「全部『追星に誘う』の機能にしていいよ。どの共有ルートでも」）。文と注記は、ファンが開いたときと、発信者の側（「追星に誘う」・自分の発信者ページ）で分ける（下の「誘う用」）。

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「リンクを共有」
- 面（角丸 20 の灰色の面）：アイコン（72）、名前、`@ID`、誘う用のリンクの QR（200 角、白地に黒。ダークモードでも同じ）、リンクの行（リンクの文字とコピーの印。押すと写す）
- 「リンクを共有する」（主色の塗りのボタン）
- 「QR を画像で保存・共有」（薄い塗りのボタン）
- 注記「リンクや QR から開いた人は、アプリが無ければ App Store へ進み、入れて開くとこの発信者をフォローした状態で始まります。アプリがあれば、このページへ進みます。」

<kbd>遷移</kbd>

- 「リンクを共有する」　→　OS の共有シートに、誘う用のリンクと短い文（「{名前}の配信と予定を、追星で追えます」）を渡す
- 「QR を画像で保存・共有」　→　QR を 1024×1024 の PNG（白地に黒、余白つき）にして、OS の共有シートに渡す。共有シートの「画像を保存」で写真に保存できる（写真への保存の許可は求めない）
- リンクの行　→　リンクを写し、スナックバー「リンクをコピーしました」

<kbd>異常系</kbd>

- 発信者がファンに見せない状態（確認済みのアカウントがない・停止中）　→　状態表示（「まだ共有できません」と理由）。ボタンを出さない
- 読み込めない　→　状態表示（読み込めない）。「もう一度試す」
- 共有シートを開けない　→　スナックバー「リンクを共有できませんでした」

<kbd>誘う用（「追星に誘う」の画面）</kbd>

発信者メニューのプロフィールカードの共有のボタン（2026-11-19 本人。もとは「シェア」の「追星に誘う」）と、自分の発信者ページのメニューの「リンクを共有」から開く（届ける・広める仕様書 4.3.6）。作りは「リンクを共有」の画面と同じで、次だけを変える。見た目と文言は、本人が見て直す前提（2026-11-18）。

- タイトル「追星に誘う」
- 「リンクを共有する」で渡す文は「追星で私の配信・予定を追いかけてね」と誘う用のリンク
- 注記「このリンクから追星を入れて開いた人は、あなたをフォローした状態で始まります。」

### 2.5 投稿ビューア

#### 2.5.1 投稿ビューア

| 項目 | 内容 |
| --- | --- |
| 役割 | 投稿を、1件ずつ見る。固定ビューア（2.4.3）を出している間は、その下の領域に出し、出していなければ画面全体に出す（2026-11-19 本人） |
| 関連機能 | 投稿の取得（機能仕様書 4.4.1）、配信の再生の音の扱い（4.3.2） |
| 入口 | ホーム、発信者ページ、タイムスケジュールの詳細のパネル、固定ビューアの投稿の動画、投稿の管理（[画面定義書（設定）](screen-design-settings.md) 2.3.8） |

<kbd>構成要素</kbd>

- 画像（またはサムネイル）を大きく出す。画像は切らずに、元の縦横比のまま全体を出す。サムネイルのない文章だけの投稿は、本文を中央に大きく出す（文字数が多いほど小さくし、収まらない長文は、本文だけスクロールする）
- 動画
  - Instagram の動画（リール）と X の動画（GIF を含む）は、自動で再生し、繰り返す。読み込むまでは、サムネイルを出す
  - 固定ビューア（2.4.3）を出している間は、動画（YouTube・Instagram と X の動画・カルーセルの中の動画）を自動で流さない。サムネイルの真ん中に再生のマークを出し、押したら流す。別の投稿に移って戻ったら、また押すまで待ち、押したら止めた位置から流す（2026-11-19 本人。固定ビューアでの再生を優先する）。固定ビューアを出していなければ、自動で流す
  - YouTube の動画・ショートは、公式プレイヤーを埋め込み、音を出して自動で再生する。再生が始まるまでは、サムネイルを出す（自動再生が止められても、プレイヤーの再生ボタンを押せるようにする）。プレイヤーには、下の本文や右の数を重ねない（YouTube の規約）。プレイヤーは 200×200 より小さくしない（縦長は幅を 200 まで広げる）。固定ビューアの下の狭い領域でそれが取れなければ、流さずにサムネイルだけを出す（2026-11-19 本人）
  - アプリで再生できない動画（機能仕様書 4.4.1）は、SNS を問わず、サムネイルに再生のマークと「この動画はアプリ上では再生できません」を重ねる（固定ビューアでは、再生のマークだけ）。YouTube は、公式プレイヤーがエラーを返した・読み込めない・準備ができないまま20秒過ぎたときに、再生できないとみなす
  - 動画を流している間は、上の固定ビューアを一時停止し、後ろで流している埋め込みビューアの音を消す。動画を止める・別の投稿に移る・ビューアを閉じると、固定ビューアを流し直し、埋め込みビューアの音を戻す（機能仕様書 4.3.2・4.3.5）
- カルーセル（Instagram のカルーセルと、画像・動画が2つ以上ある X の投稿）は、画像と動画を横に並べる。下に何枚目かを表す点を、上に「{n}/{枚数}」を出す。中の動画は、表示中のときだけ再生する（固定ビューアのボタンは出さない）。見ていた枚は、前後の投稿へ移って戻っても覚えておく
- 左上に、閉じるボタン
- 再生できる動画（YouTube の動画・ショート、動画の取れた Instagram と X の動画）では、左下の、投稿者の行のすぐ上に、固定ビューアのボタンを出す。見た目は、下部ナビの固定ビューアのコントローラー（すりガラスの丸と、中のアイコン）に寄せる。再生できないと分かったら、固定ビューアのボタンを隠す（2026-11-18 本人。前は閉じるボタンの右に出していた）
- 下に、アイコン、名前、投稿元のバッジ、本文（画像や動画のある投稿では、途中で切る）、投稿からの時間。X の投稿は、バッジの代わりに行の右端に「X の投稿者の行」（2.2.1）を出し、投稿からの時間の後ろに「· Xで見る」を出す
- 右下に、視聴数と、「開く」ボタン。映像や本文のじゃまにならないよう、小さいアイコンと字にし、薄い白で出す。押せる範囲は 48 四方より狭くしない（2026-11-18 本人）
- 下部ナビは出さない
- 固定ビューアの下に出しているときも、閉じるボタン・上下と左右のスワイプ・拡大・固定ビューアのボタン・視聴数と「開く」は、狭い領域の中でそのまま使える。固定ビューアは、ビューアを開いたまま操作できる
- 固定ビューアの下に出しているときは、中身（画像・動画・カルーセルの中の画像と動画・文章だけの投稿の本文・YouTube のプレイヤー）を、上の閉じるボタンと、下の投稿者の行・本文・右下の操作を避けた残りの高さの、上下の真ん中に置く。中身の上と下に、同じだけの空きができる。画面全体に出しているときの置き方は変えない（2026-11-19 本人）

<kbd>遷移</kbd>

- 上下のスワイプ　→　前後の投稿へ。順は、開いた画面で決まる（ホームは全体タイムライン、発信者ページはその推しの投稿を新しい順、タイムスケジュールはその推しの、選んだ日の投稿を新しい順。固定ビューアから開いたときは、その投稿だけで、前後に移らない）
- 右へのスワイプ、閉じるボタン　→　閉じる
- 左へのスワイプ（再生できる動画）　→　固定ビューアのボタンと同じ
- 左へのスワイプ（画像・文章だけの投稿、再生できない動画）　→　何もしない（指について少し動き、離すと戻る）
- 左右のスワイプは、払っている間、投稿が指について横に動く。速く払うか、画面の幅の 30% より多く動かすと決まり、足りなければ戻る。YouTube の映像の上では払えない（タッチはプレイヤーが受ける）。YouTube の規約（Required Minimum Functionality。プレイヤーへのタッチで、アプリの操作を起こさない）に反するおそれがあるため、映像の上では受けないと決めた（2026-11-09）。埋め込みビューアの帯の払いを、映像の下の帯だけで受けるのと同じ理由
- カルーセル　→　左右のスワイプで画像を送る。最初の画像でさらに右へ、最後の画像でさらに左へ引っ張ると閉じる
- 「開く」　→　元の SNS を、外部で開く
- 下のアイコン・名前　→　ビューアを閉じ、推しのタブに発信者ページを開く。ホームとタイムスケジュールから開いたときだけ。発信者ページから開いたときは、押せない（同じ発信者のため）
- 再生中の Instagram と X の動画を押す　→　一時停止・再開。止めている間は、再生のマークを出す（YouTube は、公式プレイヤーの操作を使う）
- 画像と動画ファイル（Instagram と X の動画）の拡大　→　2本の指で広げる・縮める。ダブルタップで 2.5 倍に拡大し、もう一度ダブルタップで元に戻す。上限は 4 倍。拡大している間は、1本の指で動かして見られ、上下・左右のスワイプで次・前の投稿やカルーセルの次・前の画像へ送らず、右へのスワイプで閉じもしない。元の大きさに戻ると、送れる。次の投稿へ移ったら、拡大は元に戻す。YouTube の埋め込みは拡大しない（2026-11-18 本人）
- 固定ビューアのボタン　→　ビューアを閉じ、動画を見ていた位置から固定ビューアで流し続ける（2.4.3。下部ナビのスイッチも入れる）
- 再生できない動画（再生のマークと文言）　→　元の SNS を、外部で開く
- 本文の URL　→　外部で開く
- 投稿からの時間　→　元の SNS の投稿を、外部で開く

### 2.6 通報

#### 2.6.1 通報（シート）

| 項目 | 内容 |
| --- | --- |
| 役割 | 発信者・イベントの公演・リンク集のリンクの問題を、運営に通報する |
| 関連機能 | 通報（機能仕様書 4.2.7） |
| 入口 | 発信者ページのメニューの「通報する」、予定の詳細と詳細のパネル、イベントの詳細の「この予定を通報する」（[画面定義書（スケジュール）](screen-design-schedule.md) 2.1.3・2.1.5・2.3.2）、発信者ページのリンク集の確認のダイアログの「このリンクを通報する」（2.4.1） |

<kbd>構成要素</kbd>

- ボトムシート。見出し「通報する」と、対象（発信者の名前、予定のタイトル、リンクの題名のどれか）
- 理由の選択（1つ）：「なりすまし」「不適切な内容」「危険なリンク」「その他」
- 「詳しい内容（任意）」：入力欄（500文字まで）
- 注記（「運営が内容を確かめ、必要に応じて表示を止めます。結果はお知らせしません。」）
- 「送信」ボタン

<kbd>入力項目・バリデーション</kbd>

- 理由は必須。選ぶまで「送信」を押せない。
- 詳しい内容は500文字まで。

<kbd>遷移</kbd>

- 「送信」　→　通報を送り、シートを閉じる。スナックバー「通報しました。運営が確認します」
- 下へ引く、背面を押す　→　送らずに閉じる

<kbd>異常系</kbd>

- 24時間以内に、同じ対象を通報済み　→　シートは閉じずに、スナックバー「この内容は、すでに通報を受け付けています」
- 送れない　→　シートは閉じずに、スナックバー「通報できませんでした」
