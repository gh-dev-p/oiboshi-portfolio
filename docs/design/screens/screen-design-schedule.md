## 1. 本書の目的・範囲

- 各画面の詳細は、画面名の見出しごとに、役割・入口・構成要素・入力・遷移・異常系を書く。
- 全画面に共通するルール（下部ナビ、ヘッダー、状態表示、一覧の読み直し、タブの受け持ち）は、[画面定義書 5.1](screen-design.md#51-共通ルール) を参照する。下部ナビは、本書のどの画面にも出す。
- 予定を何として出すか（予約・イベント・実績、終了時刻のない予定の長さ、読む件数）は、[機能仕様書](../specs/functional-spec.md) 4.5 を参照する。本書は、出し方を書く。
- 予定の見分けは、プラットフォームの色とアイコンで行う。推しごとの色は使わない（推しの好みに偏ると、画面がほぼ一色になるため。決定事項 5）。色の値は Figma が正。

## 2. 各画面の詳細設計

### 2.1 タイムスケジュール

#### 2.1.1 タイムスケジュール

| 項目 | 内容 |
| --- | --- |
| 役割 | 推し全員の予定を、縦軸が時間、列が推しごとの表で見る |
| 関連機能 | 配信の予約、イベント、実績（機能仕様書 4.5.1〜4.5.4） |
| 入口 | 下部ナビのスケジュール |

<kbd>構成要素</kbd>

- ヘッダー：左に年月（例：「2026年10月」）、右に「配信・投稿・予定のない推しを隠す」「絞り込み」「カレンダーへ」のアイコン。「隠す」と「絞り込み」は、オンの間（隠している・絞り込みが効いている）、アイコンの後ろに主の色の丸を敷き、アイコンを丸の上の色（白）にして、オフとひと目で見分けられるようにする。読み上げでもオン・オフを伝える。絞り込みは、推しを全員出していない・プラットフォームや内容（配信・投稿・イベント）を何か外しているときをオンとする（「隠す」は数えない。2026-11-19 本人「絞り込み系のアイコンが、今 ON なのか OFF なのか分かるようにしてほしい」。前は、「隠す」だけをアイコンの塗りと色で分けていて、分かりにくかった）
  - 固定ビューア（[画面定義書（ファン向け）](screen-design-fan.md) 2.4.3）を出している間は、ヘッダー（年月の帯）を出さず、その分だけ表を上まで広げる。月はどこにも出さない。3つのアイコンは、丸いボタン（下部ナビの丸と同じすりガラス）にして、表の右下に縦に並べて浮かせる（上から「隠す」「絞り込み」「カレンダーへ」。下部ナビと、コントローラーのヒントに重ならない所。詳細のパネルを開いているときは、パネルの後ろに隠す。2026-11-18 本人）。押したときの動き・押せないとき・オンの見え方・知らせは、ヘッダーのときと同じ（2026-11-18 本人）
- 週ストリップ：1週間（日〜土）。選んだ日に印。今日も、ほかの日と同じく曜日を出し（2026-11-19 本人「日付の表示で今日がいつかは一目でわかる」。前は、曜日の代わりに「今日」と出していた）、選んでいなくても分かる印（日付の枠と、曜日・日付の色）を付ける。日付の下に点は出さない（2026-11-18 本人。前は、絞り込んだあとの予定か投稿がある日の下に点を出していた。月の表示の点は残す）。固定ビューアを出している間は、曜日の行をなくし、日付の右に曜日を小さく並べて1段にする（例：「18 火」。今日も「19 水」のように曜日を出す）。選んだ日・今日の印は横長の丸にし、色と押したときの動きは2段のときと同じ。曜日の行の分だけ表を上に広げる。消している間は2段のまま（2026-11-18 本人）
- ヘッダーと週ストリップは、上に固定する（表だけをスクロールする）。固定ビューアを出している間も、週ストリップは固定したままにする（2026-11-09 本人。ヘッダーは出さない。上の項）。ここから開く月のカレンダー・イベント一覧・イベントの詳細は、ほかの画面と同じく固定しない（[画面定義書 5.1.2](screen-design.md#512-ヘッダー)）
- 列ヘッダー：推しごとのアイコンだけ（読み上げでは名前を読む）
- 「終日」の帯：時刻のない予定を、列の上にピルで出す。ない日は帯を出さない
  - ピルはプラットフォームのアイコン（詳しい表示ではタイトルも）。同じ推しに2件以上なら、先頭の1件を「{タイトル} +{残りの件数}」で出す
  - 時刻未定の公演もこの帯に出し、ピルに「時刻未定」の印を付ける（読み上げでも伝える。機能仕様書 4.5.2）
- 時間軸：最初は24時間を1画面に収める。左に時刻のラベル（0:00 と 24:00 を含む）。上下の端は、余白を取って跳ね返す
- 現在時刻の線：今日を選んでいるときだけ。左端に時刻のタグ
- 予定のブロック（配信とイベントの公演）：時間の長さを持たせて列の中に出す。配信とイベントの公演は同じ見え方（イベントの公演は汎用のアイコン）
  - 終わった予定・配信中・これからの予定で見え方を変える（終わった予定は薄く）
  - 終了時刻のない予定は、イベントの公演はその日の終わり（24:00）まで、配信は1時間で描き、終端をフェードさせる（機能仕様書 4.5.3。2026-11-19 本人）。時刻は開始だけ（例：「21:00〜」）。配信中なら、今の時刻まで伸ばして、その先をフェードさせる
  - 予約のない配信中の配信も、開始がその日ならブロックで出す。終わった配信（実績）は、実際の開始から終了までを、終わった予定と同じく薄く出す
  - 日をまたぐ予定は、その日の 0:00・24:00 で切る
- 投稿チップ：投稿した時刻の位置から下へ伸ばす、時刻なしの四角。縮小しているときは、拡大より長く伸ばす。終わった投稿は薄く出す
- 「+N」：近接した投稿をまとめた四角（薄くしない）。SNS が混ざるときは、含まれる SNS の小さなアイコンを件数の左に並べ、入りきらなければ件数だけを出す。読み上げは、件数と SNS（例：「3件の投稿（Instagram・X）」）

<kbd>表示の規則</kbd>

- 表は、ほかの画面と同じく、画面のいちばん下（下部ナビの後ろ）まで伸ばし、下部ナビはその上に浮かせる。24時間を1画面に収める高さは、下部ナビより上の部分で決める。ただし、固定ビューアを出している間は、0:00 の線が表の上の端（上の帯のすぐ下）、24:00 の線が画面のいちばん下の端（下部ナビの後ろ）に来る高さにする（下部ナビと重なってよい。表が狭いので、少しでも大きく出すため。2026-11-19 本人）。表の下の端には下部ナビの高さぶんの余白を入れ、24:00 の線と最後の予定が下部ナビより上に来るまでスクロールできるようにする（2026-11-18 本人。前は、表を下部ナビの上で切っていた）
- 下部ナビのスケジュールを、スケジュールを開いているときにもう一度押すと、今日の今の時刻を、表の見えている部分（下部ナビより上。詳細のパネルを開いていれば、パネルより上）の真ん中へ移す（2026-11-18 本人）
  - 別の日や別の週を見ていたら、今日に戻してから移す。上に別の画面（月のカレンダーなど）を開いていたら、スケジュールに戻ってから移す
  - 24時間を1画面に収めているときは、週ストリップの「今日」を押したときと同じく、縦を拡大してから移す
  - 真ん中にすると上や下にはみ出すとき（0時ごろ・24時ごろ）は、端で止める
  - 発信者のナビ（スケジュールは楕円の中）でも同じ
- ピンチ：縦と横を別々に変える。2本の指が横に並べば横、縦に並べば縦。指の間の時刻・列を動かさずに保つ。
  - 縦：1時間の高さを途切れなく変える。いちばん小さいと24時間を1画面に収める。
  - 横：1画面に並べる推しを5人〜3人で変える（最初は5人）。推しが少なければ列を広げて幅に収め、1人なら横のピンチをしない。
- ダブルタップ：最初の表示と、拡大（3人並び）を切り替える。拡大では、今日なら今の3時間前、ほかの日は 17:00 を上端に置く。戻すと 0:00 を上端に置く。
- 詳しい表示（文字が入る大きさのとき）：予定のタイトル（タイトルのない配信は「配信」）、余裕があれば時刻とプラットフォーム名。投稿チップは本文（なければ投稿の種類）。それより小さいときは、アイコンだけ。
- 重なり：画面の上で縦に重なるかで決める（縮小と拡大で変わる）。重ならない要素は、列の幅いっぱいに出す。
  - 同じ推しの配信同士：列を左右に等分する。
  - 配信と投稿：配信を左半分、投稿を右半分に出す。右半分の投稿は、近接していれば「+N」、離れていれば横に並べる。
  - 投稿チップ同士：横に並べる。
  - 近接した投稿（前の投稿から30分以内。続けて近接すれば同じまとまり）は、配信がなくても「+N」にまとめる。
- 1分ごとの読み直し（画面定義書 5.1.4）で、現在時刻の線と、終わった予定・配信中の見え方も変わる。

<kbd>入力項目・バリデーション</kbd>

- 日付：週ストリップで選ぶ。読み込むあいだは、前の日の表を前の日の時刻のまま出しておく（予定が一瞬 0:00 に寄らないように）。
- 絞り込み：絞り込み（シート。2.1.4）で決めた推し・プラットフォーム・内容で絞る。

<kbd>遷移</kbd>

- 週ストリップの日　→　その日に切り替える
- 週ストリップの今日（今日を選んでいるときにもう一度）　→　現在時刻を、表の上のほうへ移す。24時間を1画面に収めているときは、縦を拡大してから移る。前の日の表を出して読み込んでいるあいだは、何もしない
- 週ストリップの左右のスワイプ　→　前後の週の同じ曜日に切り替える
- 列ヘッダーのアイコン　→　発信者ページ
- 「配信・投稿・予定のない推しを隠す」　→　オン・オフを切り替え、スナックバー（オン「配信・投稿・予定のない推しを隠しました」、オフ「すべての推しを表示しました」）。オンのとき、選んだ日に出すもの（予定・投稿・終日の予定・配信中）がない推しの列を出さない。全員にないときは、列を隠さず、予定なしのカード（2.1.2）を出す。初期値はオフ。アプリを起動しているあいだ保つ
- 絞り込み　→　絞り込み（シート。2.1.4）。推しがいないとき、読み込めていないときは、開かない
- 「カレンダーへ」　→　みんなのカレンダー（2.2.1）。タイムスケジュールで選んでいる日を選んで開く。絞り込みは引き継がない。推しがいないときは、開かない
- 配信・イベントの公演のブロック、「終日」のピル、投稿チップ、「+N」　→　詳細のパネル（2.1.3）
- 表の何もないところ　→　詳細のパネルを閉じる

<kbd>異常系</kbd>

- 読み込み中　→　スケルトン（ヘッダーと週ストリップは出す）
- 初めて読み込めない　→　状態表示（読み込めない）
- 更新に失敗（日や絞り込みの切り替えを含む）　→　内容を残したまま、スナックバー「更新できませんでした」と「再試行」
- 推しが0人　→　タイムスケジュール（推しがいない。2.1.6）
- その日の予定がない　→　タイムスケジュール（予定なし。2.1.2）

#### 2.1.2 タイムスケジュール（予定なし）

| 項目 | 内容 |
| --- | --- |
| 役割 | 選んだ日に、出すもの（予定・投稿・終日の予定）がないときの状態 |
| 関連機能 | 空の状態 |
| 入口 | タイムスケジュールで、選んだ日に、絞り込んだあとの出すものがない |

<kbd>構成要素</kbd>

- タイムスケジュールと同じ表（「終日」の帯は出さない）の上に、小さなカードを重ねる：アイコン、「この日の予定はありません」、「ほかの日は、上の日付から選べます。」。カードは表と一緒にスクロールする

#### 2.1.3 詳細のパネル

| 項目 | 内容 |
| --- | --- |
| 役割 | 表の要素（配信・予定・投稿）の中身を、表を見たまま、テンポよく確かめる |
| 関連機能 | 予定の閲覧、配信の再生、投稿の閲覧 |
| 入口 | タイムスケジュールの、予定のブロック、「終日」のピル、投稿チップ、「+N」 |

<kbd>構成要素</kbd>

- 表の下に重ねるパネル。背面は暗くせず、表はそのまま触れる。引き手と閉じるボタン。高さは開くときに決め、開いているあいだは変えない（多ければパネルの中でスクロール）
- パネルは画面のいちばん下（下部ナビの後ろ）まで伸ばし、中身も下部ナビの後ろまで流す。スクロールの終わりに下部ナビの高さぶんの余白を入れ、中身の最後（ボタンなど）がナビに隠れないようにする（2026-11-18 本人）
- 押した要素を表の上で目立たせ、ほかを薄くする
- 中身（どれもカード）
  - 配信中の配信：推しのアイコン、名前、「配信中」、配信タイトル（なければ「配信」）、プラットフォームのアイコン、「配信を見る」
  - 配信の予定・イベントの公演・「終日」の予定：予定の詳細（2.1.5）と同じ中身
  - 投稿チップ・「+N」：推しのアイコン、「{推し}の投稿」、時刻と件数（例：「21時ごろ ・ 2件」。いちばん古い投稿の時刻）、投稿の一覧。各行は、投稿元のバッジ、投稿元と時刻（例：「YouTube ・ 21:05」）、本文（なければ投稿の種類）、YouTube と Instagram はサムネイル、「>」。X の投稿は、バッジと投稿元と時刻の代わりに、X の投稿者の行（[画面定義書（ファン向け）](screen-design-fan.md)のホーム）を出す

<kbd>表示の規則</kbd>

- 開いたら、押した要素の時刻を、パネルに隠れない位置へスクロールする。24時間を1画面に収めているときも、パネルのぶん表の下に余白を足す。「終日」の予定では、スクロールしない
- 開いたまま別の要素を押すと、パネルは出したまま中身だけを替え、同じく時刻を合わせる。パネルの中のスクロールは上に戻す
- 日を切り替えて新しい日の表が出たとき、読み直しや絞り込みで要素がなくなったときは、閉じる
- 左右のスワイプで中身を送る（2026-11-18 本人）。左へ払うと次、右へ払うと前の要素
  - 順番は、表の列を左から、列の中は「終日」のピル、そのあと配信・予定のブロックと投稿チップ・「+N」を時刻の順（同じ時刻ならブロックが先）
  - その推しの最後でさらに左へ払うと、右隣の推しの最初へ。最初で右へ払うと、左隣の推しの最後へ
  - 送れるのは、今表に出している日の、表に出ている要素だけ（絞り込み・隠した推しの列は入れない）。全体の最初と最後では送らない
  - 送ったら、開いたときと同じく時刻をパネルに隠れない位置へ合わせ、列が横に見えていなければ見える位置まで横にスクロールする。パネルの中のスクロールは上に戻す
  - パネルの中の縦のスクロール、下へ払って閉じる動きとは、指を動かした向きで分ける

<kbd>遷移</kbd>

- 「配信を見る」　→　推しのタブに、発信者ページ（[画面定義書（ファン向け）](screen-design-fan.md) 2.4.1）。固定ビューアで流しているものは変えない（2026-11-19 本人）
- 「発信者のページを開く」「リンクを開く」「編集」「この予定を通報する」　→　予定の詳細（2.1.5）と同じ
- 投稿の行　→　投稿ビューア。上下のスワイプで、その推しの、選んだ日の投稿（絞り込んだあと）を、新しい順に移る
- 閉じるボタン、下へ払う、表の何もないところ　→　パネルを閉じる

#### 2.1.4 絞り込み（シート）

| 項目 | 内容 |
| --- | --- |
| 役割 | タイムスケジュール、またはみんなのカレンダー（2.2.1）に出す推し・プラットフォーム・内容を絞る |
| 関連機能 | スケジュールの絞り込み（機能仕様書 4.5.5） |
| 入口 | タイムスケジュール・みんなのカレンダーのヘッダーのアイコン |

<kbd>構成要素</kbd>

- ボトムシート（背面は暗くする）。タイトル「絞り込み」と、右に「リセット」
- 「表示する推し」：選んだ人数（全員なら「全員」、ほかは「3人」など）と「>」の1行
- 「プラットフォーム」：チップ（YouTube・X・Instagram・ツイキャス・Twitch・イベント）。選んだものと選んでいないものを見分けられるように出す。「イベント」は、プラットフォームのない予定（イベントの公演）のチップ
- 「表示する内容」：スイッチ（「配信」「投稿」）。イベントの公演は、ここではなく、SNS の並びの「イベント」のチップで出し入れする（2026-11-09 本人）。どのスイッチがどの予定に効くかは、機能仕様書 4.5.5
- 適用のボタン：選んだ人数と SNS の数を出す（例：「3人・4つのSNSで表示」。全員でも人数で出す。「イベント」は SNS に数えない）

<kbd>入力項目・バリデーション</kbd>

- 推し：複数。1人以上。初期値は全員。外した推しだけを隠す（あとからフォローした推しは出す）。
- プラットフォーム：複数。SNS と「イベント」のうち1つ以上。初期値は全部。
- 表示する内容：初期値は、3つともオン。
- 推しを1人も、または SNS も「イベント」も1つも選んでいないときは、適用のボタンを押せない。
- 絞り込みは、タイムスケジュールとみんなのカレンダーで別々に持ち、アプリを起動しているあいだ保つ。

<kbd>遷移</kbd>

- 「リセット」　→　シートの中の選択を初期値に戻す（適用のボタンを押すまで、表には反映しない）
- 「表示する推し」の行　→　推しの選択（2.1.4.1）。シートは閉じず、中身を横に送る
- 適用のボタン　→　絞り込みを反映して、シートを閉じる
- 下へ引く、背面を押す　→　変えた内容を捨てて、シートを閉じる

##### 2.1.4.1 推しの選択（シートの中）

<kbd>構成要素</kbd>

- 左上に戻るボタン、タイトル「表示する推し」、右に「すべて選ぶ」（全員を選んでいるときは「すべて外す」）
- 推しの一覧。各行に、アイコン、名前、チェック。選んでいない推しは、アイコンと名前を薄くする

<kbd>遷移</kbd>

- 行　→　その推しを選ぶ・外す
- 「すべて選ぶ」「すべて外す」　→　全員を選ぶ・外す
- 戻るボタン　→　絞り込み（シート）に戻る。選んだ内容は残す

#### 2.1.5 予定の詳細（シート）

| 項目 | 内容 |
| --- | --- |
| 役割 | 配信の予定と、イベントの公演の内容を見る |
| 関連機能 | 予定の閲覧 |
| 入口 | 月のカレンダーの予定の行、発信者ページの次の予定。タイムスケジュールでは、同じ中身を詳細のパネル（2.1.3）に出す |

<kbd>構成要素</kbd>

- ボトムシート（背面は暗くする）。タイトルは置かず、カードを出す
- 発信者の行：アイコン、名前、種類（「配信の予定」または「イベント」）、プラットフォームのアイコン（イベントは汎用のアイコン）
- タイトル（タイトルのない配信は「配信」）と状態のチップ（配信は「これから」か「終了しました」。実績も「終了しました」。イベントの公演は「イベント」。2026-11-09 本人）
- 日時：開始から終了まで（例：「10月16日（木）21:00〜22:00」）。終了が別の日なら終了の日付も出す。終了時刻がなければ開始だけを出し、「終了時刻は未定です」を添える（長さは出さない。2026-11-19 本人）。終日は「10月16日（木） 終日」、時刻未定の公演は「10月16日（木） 時刻未定」
- 会場とリンク（あるときだけ）。リンクは「リンク」（イベントなら「チケット」）と、「押すと、外部のページが開きます」
- 「リンクを開く」（イベントなら「チケットを見る」）。広告のリンクなら「PR」のラベルを付ける
- 「発信者のページを開く」。発信者ページの次の予定と、発信者ページから開いた月のカレンダーから開いたときは、出さない
- 「編集」（イベントの公演で、自分がオーナーのときだけ）
- 「この予定を通報する」（イベントの公演で、自分がオーナーでないときだけ）

<kbd>遷移</kbd>

- 「リンクを開く」　→　確認のダイアログ（「外部のサイトを開きます」、行き先のドメイン、「開く」「キャンセル」）。「開く」で外部のページを開く。`https://` で始まらないリンクは開かず、スナックバー「ページを開けませんでした」（機能仕様書 4.5.3）
- 「発信者のページを開く」　→　シートを閉じて、発信者ページ
- 「編集」　→　シートを閉じて、イベントの編集（[画面定義書（設定・発信者向け）](screen-design-settings.md) 2.3.9）
- 「この予定を通報する」　→　通報（シート。[画面定義書（ファン向け）](screen-design-fan.md) 2.6.1）
- 下へ引く、背面を押す　→　シートを閉じる

#### 2.1.6 タイムスケジュール（推しがいない）

| 項目 | 内容 |
| --- | --- |
| 役割 | フォロー中の推しが0人のときの空の状態 |
| 関連機能 | 空の状態 |
| 入口 | タイムスケジュールで、フォロー中の推しが0人 |

<kbd>構成要素</kbd>

- ヘッダーと週ストリップは、タイムスケジュールと同じ
- 状態表示：アイコン、「推しの予定が、ここに並びます」、「推しをフォローすると、配信やイベントを、時間の表で見られます。」。ボタンは置かない
- 絞り込みと「カレンダーへ」は、押せない見た目にし、押しても何もしない

### 2.2 月のカレンダー

#### 2.2.1 月のカレンダー

| 項目 | 内容 |
| --- | --- |
| 役割 | 月単位で、予定と実績（行われた配信と投稿）を見る。1人の予定と、推し全員の予定（みんなのカレンダー）の両方に使う |
| 関連機能 | 配信の予約、イベント、実績 |
| 入口 | タイムスケジュールの「カレンダーへ」（推し全員。スケジュールのタブ）、発信者ページのカレンダーへのボタン（1人。発信者ページと同じタブ。[画面定義書 5.1.8](screen-design.md#518-タブの受け持ち)） |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル（出す推しが1人なら「{名前}のカレンダー」、2人以上なら「みんなのカレンダー」）。みんなのカレンダーだけ、右に絞り込みのアイコン（2.1.4 と同じシート。グリッドの点と、選んだ日のパネルの両方に効く）。絞り込みが効いている間は、タイムスケジュールのヘッダーと同じく、主の色の丸を敷いたオンの見た目にする（2026-11-19 本人）。タイムスケジュールから開いても、推しが1人なら1人のカレンダーと同じにする
- 月のナビ：左に年月、右に前の月・次の月の矢印
- 曜日の行と月のグリッド：その月の日付だけ（前後の月の日は出さない）。日ごとに、種類ごとの小さな点を、配信・投稿・それ以外の予定（イベント）の順に最大3つ並べる（順は 2026-11-19 本人）。配信とそれ以外の予定は、開始がその日の予定（行われた配信を含む）があるとき、投稿は、その日に投稿があるとき（選んだ日のパネルに出す投稿と同じもの。表示するコンテンツと絞り込みに従う）に出す。点の色は、配信が青（現在時刻の線と同じ色）、投稿が緑（キャラクターの緑）、イベントが赤（ライブの色）で、ライト・ダークのどちらでも背景と見分けられる色にする（2026-11-19 本人「カレンダーのドットなんだけど、配信・投稿・イベントの三色で分けてほしい」。前は投稿を灰色にしていたが、背景に沈んで見分けにくかった）。グリッドの下に、点と「配信」「投稿」「イベント」の小さな凡例を、控えめな文字で出す。選んだ日の点は、3つとも同じ選んだ日の色にする（2026-11-18 本人）。投稿は、その月のデータとして読んでいるものから数え、点のために読み込みを足さない。選んだ日に印
- 選んだ日のパネル（見出し「{月}月{日}日（{曜日}）」）：予定の行を開始の時刻順に並べ、投稿の行を最後に置く
  - 推しが2人以上なら、時刻の右に推しのアイコンを出す（行のタイトルに名前は付けない。読み上げでは名前を読む）。投稿の行は、投稿した推しのアイコンを2人までずらして重ねる
  - 時刻は1行で出す。終日は「終日」、時刻未定の公演は「時刻未定」
  - イベントの公演の行：時刻、タイトル、会場（あれば）。リンクがあれば右に「チケット」（広告なら「PR」）、なければ汎用のアイコン
  - 配信の行（予約と実績）：時刻、タイトル、プラットフォームのアイコン
  - 投稿の行：時刻の位置に「投稿」、「この日に行われた投稿」、「{件数}件」、投稿元のアイコン（重ねずに並べる）
  - 予定も投稿もない日は「この日の予定はありません」

<kbd>入力項目・バリデーション</kbd>

- 最初に選ぶ日：タイムスケジュールから開いたら、そこで選んでいた日。発信者ページから開いたら、今日。
- 月を移ったときに選ぶ日：今日を含む月なら今日、ほかの月は1日。

<kbd>遷移</kbd>

- 日付　→　その日のパネルに切り替える
- 前の月・次の月　→　月を移る
- 絞り込みのアイコン　→　絞り込み（シート）。読み込めていないときは、開かない
- 予定の行（配信・イベントの公演・終日の予定）　→　予定の詳細（シート。2.1.5）
- 投稿の行　→　押せない
- 「リンク」　→　予定の詳細（2.1.5）の「リンクを開く」と同じ

<kbd>異常系</kbd>

- 読み込み中　→　スケルトン
- 初めて読み込めない　→　状態表示（読み込めない）
- 更新に失敗　→　内容を残したまま、スナックバー「更新できませんでした」と「再試行」

### 2.3 イベント一覧

#### 2.3.1 イベント一覧

| 項目 | 内容 |
| --- | --- |
| 役割 | これからのイベントを、日付順に一覧で見る。1人のイベントと、推し全員のイベントの両方に使う |
| 関連機能 | イベント（機能仕様書 4.5.2・4.5.3） |
| 入口 | ホームの「イベント」の「ほか {N} 件」（推し全員。ホームのタブ）、発信者ページの「イベント」の「ほか {N} 件」（1人。発信者ページと同じタブ。[画面定義書 5.1.8](screen-design.md#518-タブの受け持ち)） |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル（推しが1人なら「{名前}のイベント」、2人以上なら「みんなのイベント」）
- 出すのは、これから1年（366日）以内のイベントの公演。開催中のもの（終了時刻の前。終了時刻がなければ開始の前。終日なら、その日のあいだ）は出し、終わったものは出さない（ホームの「イベント」と同じ）
- 月の見出し（「2026年11月」）で区切り、開始の日時順に並べる
- イベントの行：左に日付のブロック（上に月「11月」、下に日「12」を大きく）、タイトル、「{曜日} {開始の時刻}・{会場}」（終日は「終日」、時刻未定は「時刻未定」。会場がなければ会場を省く）。推しが2人以上なら、推しのアイコン（小）と名前
- 1件もないときは、状態表示（「これからのイベントはありません」、「イベントが登録されると、ここに出ます」）

<kbd>遷移</kbd>

- イベントの行　→　イベントの詳細（2.3.2）
- 引き下げ（空のときも）　→　読み直す
- 右へ払う　→　前の画面

<kbd>異常系</kbd>

- 読み込み中　→　スケルトン
- 初めて読み込めない　→　状態表示（読み込めない）
- 更新に失敗　→　内容を残したまま、スナックバー「更新できませんでした」と「再試行」

#### 2.3.2 イベントの詳細

| 項目 | 内容 |
| --- | --- |
| 役割 | 1つのイベントの中身を見て、チケットサイトへ移る |
| 関連機能 | イベント、リンク、通報 |
| 入口 | ホーム・発信者ページの「イベント」の行、イベント一覧の行。開いたタブの中で、いまの画面の上に重ねる（[画面定義書 5.1.8](screen-design.md#518-タブの受け持ち)）。月のカレンダーからは予定の詳細（2.1.5）、タイムスケジュールからは詳細のパネル（2.1.3）に出す |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「イベント」
- 上の段：日付のブロック（イベント一覧と同じ）とタイトル。終わったイベント（2.3.1 と同じ判定）なら、「終了しました」のチップ
- 発信者の行：アイコン、名前、右向きの矢印。発信者ページ（とそこから開いたイベント一覧）から開いたときは、矢印を出さず、押せない
- 日時の行：予定の詳細（2.1.5）と同じ書き方
- 会場の行（あるときだけ）
- チケット（リンクがあるときだけ）：見出し「チケット」の下に、登録したリンクごとに「{サイト名}で購入」（例：「チケットぴあで購入」。知らないサイトはドメイン）。1本目を目立つボタン、2本目からは薄いボタン。広告のリンクなら「PR」。下に「押すと、外部のページが開きます」。チケットの販売の状況は出さない（決定事項 1）
- 「編集」（自分がオーナーのときだけ）
- 「この予定を通報する」（自分がオーナーでないときだけ）

<kbd>遷移</kbd>

- 発信者の行　→　推しのタブに、発信者ページ
- チケットのボタン　→　予定の詳細（2.1.5）の「リンクを開く」と同じ
- 「編集」　→　イベントの編集（[画面定義書（設定・発信者向け）](screen-design-settings.md) 2.3.9）
- 「この予定を通報する」　→　通報（シート。[画面定義書（ファン向け）](screen-design-fan.md) 2.6.1）
- 右へ払う　→　前の画面
