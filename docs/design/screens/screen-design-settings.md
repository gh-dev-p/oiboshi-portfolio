## 1. 本書の目的・範囲

- 各画面の詳細は、画面名の見出しごとに、役割・入口・構成要素・入力・遷移・異常系を書く。画面IDは振らず、画面は名前で呼ぶ。
- 全画面に共通するルール（下部ナビ・ヘッダー・状態表示・SNS の並び）は、[画面定義書 5.1](screen-design.md) に従う。この章の画面は、設定のタブ・発信者のタブの中で開き、下部ナビを出す（画面定義書 5.1.1・5.1.8）。
- 「状態表示（読み込めない）」は、画面定義書 5.1.3 の「読み込めませんでした」「通信の状態を確認して、もう一度お試しください。」「もう一度試す」を指す。読み込み中のスケルトンも 5.1.3 に従い、画面ごとには書かない。
- 時間のかかる操作（ログアウト・退会・表示しない発信者を戻す・登録・取り戻し・保存・取り込み・購入・復元）のあいだは、画面に薄い幕をかけて、操作を止める。
- 振る舞いの決まりは、[機能仕様書](../specs/functional-spec.md)を正とし、本書は画面の出し方だけを書く。決まっていない事項は、GitHub の Issue を参照する。

## 2. 各画面の詳細設計

### 2.1 設定

#### 2.1.1 設定

| 項目 | 内容 |
| --- | --- |
| 役割 | 設定のハブ。ファンと発信者で、中身が少し変わる |
| 関連機能 | 通知、画面モード、言語、発信者の登録、ログイン方法、サポート、退会 |
| 入口 | 下部ナビの設定。発信者は、発信者メニューの右上の歯車 |

<kbd>構成要素</kbd>

- ヘッダー：左にタイトル「設定」（タブの本体なので、戻るは置かない）。固定ビューアを出している間は、ヘッダーを固定せず、中身と一緒にスクロールして上に隠す（画面定義書 5.1.2。2026-11-09 本人）
- 検索フィールド（プレースホルダ「検索」）。ファンにも発信者にも置く
- 最初のグループ（見出しなし）：「通知」（値：オン／オフ）、「画面モード」（値：ライト／ダーク／端末の設定に従う）、「言語」（値：端末の設定に従う／日本語／English）
- 「アカウント」グループ（2026-11-10 本人）：
  - アカウント作成の前（匿名のユーザー）：「アカウント作成／ログイン」
  - アカウント作成のあと：「ログイン方法」（値：結び付けたサービスの名前。複数なら「・」でつなぐ。例：「Twitch」）と、「ログアウト」
  - 匿名かどうかは、ログイン方法を読めるまで（読めないときも）は、端末のセッションのユーザーで決める（機能仕様書 4.1.4）
  - 「表示しない発信者」（値：人数。例：「2人」。0人でも「0人」と出す。停止中などで読めない発信者は数えない）
- 「発信者として登録する」のカード（発信者として登録していない人だけ。自分の発信者を読めるまでは出さない。アカウントのグループの下、サポートの上）：角丸の面に、丸いアイコン（＋）、タイトル「発信者として登録する」、タイトルと同じ行の右に青い星のキャラクター（`app/assets/characters/blue.png`。高さ 52 の枠の中に、左の＋の円と同じ高さ 40 で、縦の中心をそろえて置く。カードの高さは枠で決まる。2026-11-10 本人）、右に「>」。紺の薄い塗り（`accentNavyFill`）と紺（`accentNavy`）の丸。説明文は置かない（2026-11-10 本人）
  - アカウント作成の前は、グレーにして押せない。キャラクターは色を変えずに薄く（不透明度 0.4）出す。タイトルの下に「先にアカウントを作成してください」
  - キャラクターは飾りなので、読み上げ（VoiceOver・TalkBack）では読まない
  - 発信者として登録した人には出さない（発信者メニューは、発信者のタブ。2.2.2）。発信者のプロフィールカードは、設定には出さない
- 「サポート」グループ：「お問い合わせ」、「利用規約」、「プライバシーポリシー」
- 一番下に、「退会」
- 画面全体の読み込み中・読み込めない表示は出さない。値（通知・ログイン方法・表示しない発信者）は、読めるまで空にする

<kbd>入力項目・バリデーション</kbd>

- 検索：表示している言語の、行の名前で絞り込む（部分一致。英字は大文字と小文字を区別しない）。グループの見出しは、合う行があるグループだけ出す。

<kbd>遷移</kbd>

- 「通知」　→　通知設定へ
- 「画面モード」　→　画面モード（シート）
- 「言語」　→　言語（シート）
- 「発信者として登録する」のカード　→　発信者として登録へ（アカウント作成の前は、押しても何もしない）
- 「アカウント作成／ログイン」　→　アカウント作成／ログイン（シート。2.1.6）。アカウントを作ったら、スナックバー「アカウントを作成しました」。ログインしたら、スナックバー「ログインしました」
- 「ログイン方法」　→　ログイン方法へ（ほかの方法を足す・外す）
- 「ログアウト」　→　確認のダイアログ（「ログアウトしますか？」「結び付けたログイン方法で、またログインできます。」、「キャンセル」「ログアウト」）のあと、ログアウトして、新しい匿名のユーザーで始め直す。設定の画面は閉じず、スナックバー「ログアウトしました」
- 「表示しない発信者」　→　表示しない発信者へ
- 「お問い合わせ」　→　メールアプリを、宛先・件名・本文の入った下書きで開く（機能仕様書 4.7.3）。サインインしていなければ、本文のユーザー ID の代わりに「（サインインしていません）」
- 「利用規約」「プライバシーポリシー」　→　公開ページを開く
- 「退会」　→　退会へ

<kbd>異常系</kbd>

- 検索に合う行がない　→　「見つかりませんでした」（出している行だけで判定する）
- ログイン方法を読めない（アカウント作成のあと）　→　「ログイン方法」の行の値に「読み込めませんでした」と、読み直しのボタン「再試行」
- メールアプリが使えない　→　お問い合わせ（ダイアログ。2.1.9）
- 公開ページを開けない　→　スナックバー「ページを開けませんでした」
- ログアウトに失敗　→　スナックバー「ログアウトできませんでした」

#### 2.1.2 通知設定

| 項目 | 内容 |
| --- | --- |
| 役割 | 配信開始の通知と予定の事前通知を、まとめてオン・オフする |
| 関連機能 | 配信開始の通知（機能仕様書 4.3.3）、予定の事前通知（届ける・広める仕様書 4.1.1） |
| 入口 | 設定の「通知」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「通知設定」
- 一番上に、次のどちらかのカード（どちらも当てはまらなければ出さない）
  - 許可カード（通知の許可を一度も求めていないとき）：「通知を許可すると、推しの配信の開始と予定をお知らせします。」と「通知を許可する」
  - 注意カード（端末の通知がオフのとき）：「端末の通知がオフになっています。配信の開始や予定をお知らせするには、端末の設定で通知を許可してください。」と「端末の設定を開く」
- 「配信と予定の通知」の行：補足「推しが配信を始めたときと、予定の前に、お知らせします」と、スイッチ。1つのスイッチで、配信開始の通知と予定の事前通知の両方を切り替える
- 注記「推しごとの通知は、それぞれの推しのページで変えられます。」

<kbd>遷移</kbd>

- 「通知を許可する」　→　OS の許可の画面を出す。許可されたら、許可カードを消し、端末を通知の送り先に登録する。許可されなかったら、注意カードに替える
- 「端末の設定を開く」　→　端末の設定アプリを開く
- アプリに戻る　→　端末の通知の許可を確かめ直す。オンになっていたら、注意カードを消し、端末を通知の送り先に登録する
- スイッチ　→　すぐに切り替えて保存する

<kbd>異常系</kbd>

- 読み込めない　→　状態表示（読み込めない）。「もう一度試す」
- 画像を作れない（通信の失敗・サーバーの失敗）　→　見本の所に「画像を作れませんでした」と「再試行」。共有のボタンは押せない
- 画像を上げられない　→　スナックバー「画像を変えられませんでした」（見本は前のまま）で、端末の通知の許可を確かめ直す
- スイッチを変えられない　→　スイッチを元に戻し、スナックバー「通知の設定を変えられませんでした」

#### 2.1.3 画面モード（シート）

| 項目 | 内容 |
| --- | --- |
| 役割 | ライト・ダークを選ぶ |
| 関連機能 | 画面モード（機能仕様書 4.7.1） |
| 入口 | 設定の「画面モード」 |

<kbd>構成要素</kbd>

- ボトムシート。タイトル「画面モード」
- 選択肢「ライト」「ダーク」。画面のプレビューと、選択中のチェックを出す
- 「端末の設定に従う」の行とスイッチ

<kbd>入力項目・バリデーション</kbd>

- 「端末の設定に従う」がオンのとき、ライト・ダークは押せない。チェックは、端末の設定で決まる側に付ける。
- 「端末の設定に従う」をオフにすると、そのときの端末の設定（ライトかダーク）に固定する。

<kbd>遷移</kbd>

- 選択肢　→　画面モードを切り替える。シートは閉じない
- 下へ引く、背面を押す　→　シートを閉じる

#### 2.1.4 退会

| 項目 | 内容 |
| --- | --- |
| 役割 | データを削除して、退会する |
| 関連機能 | 退会（機能仕様書 4.1.3） |
| 入口 | 設定の「退会」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「退会」
- 説明「退会すると、フォロー中の推し、通知や表示の設定が、すべて削除されます。この操作は取り消せません。」
- 条件つきの補足：
  - 発信者のオーナー　→　「あなたの発信者は、すぐに追星に表示されなくなり、90日後に消えます。90日のうちなら、発信者として登録の画面で、同じSNSのアカウントを連携すると、取り戻せます。」
  - iPhone 以外の端末で、Apple とほかのログイン方法を結び付けている　→　「この端末では、Apple でのサインインのひも付けを取り消せません。iPhone で退会するか、退会のあとに、iPhone の設定の「Apple でサインイン」から外してください。」
  - iPhone 以外の端末で、ログイン方法が Apple だけ　→　「Apple だけでログインしているので、この端末では本人の確認ができません。iPhone で退会してください。」。「退会する」は押せない
  - X連携プランに加入中か、加入中かを読み込めない（読み込んでいるあいだは出さない）　→　注意「退会しても、ストアのサブスクは解約されません。先に、サブスクの管理から解約してください。」と「サブスクの管理を開く」。加入中かは、サーバーの加入の状態で決める（ほかの OS や、課金を使えない端末で買った加入も分かるように）
- 「退会する」ボタンと、「キャンセル」

<kbd>遷移</kbd>

- 「退会する」　→　ログイン方法を結び付けたユーザーは、本人の確認（シート。2.1.7）のあと、データを削除する。iPhone で Apple を結び付けているときは、本人の確認は Apple だけで行い、Apple のひも付けも取り消す。匿名のユーザーは、そのまま削除する。削除したら、ウェルカムに戻る（初回起動からやり直す）
- 「サブスクの管理を開く」　→　確認のダイアログを出さずに、ストアのサブスクの管理の画面を開く（プランの「解約する」と同じ先。2.3.6）
- 「キャンセル」　→　設定へ戻る

<kbd>異常系</kbd>

- ログイン方法を読み込めない　→　スナックバー「読み込めませんでした。もう一度お試しください」。退会しない
- サブスクの管理を開けない　→　スナックバー「ページを開けませんでした」
- 削除に失敗　→　スナックバー「退会できませんでした」

#### 2.1.5 ログイン方法

| 項目 | 内容 |
| --- | --- |
| 役割 | ログインに使う、Apple・Google・X・Twitch を結び付ける・外す |
| 関連機能 | ログイン方法（機能仕様書 4.1.4） |
| 入口 | 設定の「ログイン方法」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「ログイン方法」
- 説明「結び付けたどれかで、別の端末からもログインできます。発信者は、2つ以上がおすすめです。」
- 行：Apple（iOS だけ。ほかの端末では、結び付け済みのときだけ出す）・Google・X・Twitch。アイコン、サービス名、結び付けたアカウント（メールアドレスかユーザー名。取れなければ「設定済み」、結び付けていなければ「未設定」）、右に「結び付ける」か「外す」
- 注記「SNS のアカウント連携とは別です。ログイン方法を外しても、連携は残ります。」

<kbd>入力項目・バリデーション</kbd>

- 最後の1つは外せない（「外す」を出さない）。

<kbd>遷移</kbd>

- 「結び付ける」　→　本人の確認（シート。2.1.7）のあと、その SNS のログインへ（Apple は iOS の標準のシート、ほかはアプリ内のブラウザ）。戻ると、スナックバー「{サービス名}のログインを結び付けました」。途中でやめたときは、何も出さない
- 「外す」　→　確認のダイアログ（「{サービス名}のログインを外しますか？」「{サービス名}では、ログインできなくなります。」、「キャンセル」「外す」）と、本人の確認（シート）のあと、外す。スナックバー「{サービス名}のログインを外しました」

<kbd>異常系</kbd>

- 読み込めない　→　状態表示（読み込めない）。表示済みの一覧があれば、残す
- 結び付けようとしたアカウントが、ほかのユーザーで使われている　→　スナックバー「このアカウントは、ほかのユーザーで使われています」
- 結び付けに失敗（本人の確認で、結び付けていないアカウントでログインしたときも）　→　スナックバー「結び付けられませんでした。もう一度お試しください」
- 外せない　→　スナックバー「外せませんでした。もう一度お試しください」

#### 2.1.6 アカウント作成／ログイン（シート）

| 項目 | 内容 |
| --- | --- |
| 役割 | アカウントを作るか、使ったことのあるアカウントに入る。どちらになるかは、アプリとサーバーが決める |
| 関連機能 | ログイン方法（機能仕様書 4.1.4） |
| 入口 | 設定の「アカウント作成／ログイン」、ウェルカムの「発信者の方はこちら」（匿名のとき） |

<kbd>構成要素</kbd>

- タイトル「アカウント作成／ログイン」。説明は置かない（2026-11-10 本人）。ウェルカムの「発信者の方はこちら」から開いたときだけ、「発信者として登録するには、アカウントが要ります。」を添える
- ボタン：「Appleで続ける」（iOS だけ）「Google で続行」「Xで続ける」「Twitchで続ける」
- ボタンの下に、小さく「アプリ運営用ログイン」（文字だけ。注記と同じ大きさと色。2026-11-11 本人）
- Apple と Google のボタンは、各社の決まり（背景の色・公式のロゴ・決められた文言）に合わせる（決定事項 5）。英語は「Continue with Apple」「Continue with Google」「Continue with X」「Continue with Twitch」

- そのほかの失敗　→　スナックバー「登録できませんでした。もう一度お試しください」（取り戻しは「取り戻せませんでした。もう一度お試しください」）

<kbd>構成要素</kbd>

- 「名前」：入力欄。取り込んだ項目には、チップ「下書き・{取り込み元}から」を付ける
- 「プロフィール文」：複数行の入力欄。取り込んだ項目には、同じチップを付ける
- 「ID」：「@」に続く入力欄（プレースホルダ「英小文字・数字・_・-」）と、注記「IDは、あとから変えられません。」。登録の手順から開いたときだけ入力でき、登録のあとは「@{ID}」を出すだけにする
- 「タイプ」：タイプの一覧のチップから、3つまで選ぶ（3つ選ぶと、ほかは押せない）。注記「3つまで選べます。おすすめに使います。」

<kbd>入力項目・バリデーション</kbd>

- 名前：1〜100文字（前後の空白を除き、見た目の1文字で数える）。
- ID：英小文字・数字・`_`・`-` の1〜40文字。登録のあとは変えられない。
- 取り込める項目は、名前・アイコン・プロフィール文。カバーは取り込まない。取り込みは下書きとして入るだけで、名前・プロフィール文・アイコン・カバー・タイプは、どれも保存するまで反映しない。登録の手順では、登録したときに保存する。
- 取り込み元のチップは、確認済みの SNS（登録の手順では、登録待ちの連携）。X は、X連携プランに加入している発信者（永年無料・運営・確認用を含む）だけに出す（X の API に費用がかかるため。決定事項 5）。登録の手順では、まだ加入していないので、X を出さない。取り込める SNS がなければ、チップを出さない。

<kbd>遷移</kbd>

- 「保存」　→　保存して、前の画面へ。登録の手順から開いたときは、登録まで下書きとして持つ
- 取り込み元のチップ　→　その SNS から、下書きを入れる。スナックバー「{サービス名}から、下書きを入れました」

<kbd>異常系</kbd>

- 読み込めない　→　状態表示（読み込めない）
- 名前が条件に合わずに「保存」　→　スナックバー「名前は、1〜100文字で入力してください」
- ID が条件に合わずに「保存」　→　スナックバー「IDは、英小文字・数字・_・- の1〜40文字で入力してください」
- 保存に失敗　→　スナックバー「保存できませんでした」
- 取り込みに失敗　→　スナックバー「{サービス名}から取り込めませんでした」
- 取り込める項目がない　→　スナックバー「{サービス名}に、取り込める項目がありませんでした」
- 取り込みの回数の上限に当たった　→　スナックバー「{サービス名}からの取り込みは、しばらく時間をおいてお試しください」
- タイプを読み込めない　→　タイプの欄に「タイプを読み込めませんでした」と「再試行」

#### 2.3.2 SNS（SNS の連携と表示するコンテンツ）

| 項目 | 内容 |
| --- | --- |
| 役割 | SNS のアカウントを連携し、本人のものであることを確かめる。発信者メニューから開いたときは、SNS ごとに追星に出す内容も選ぶ |
| 関連機能 | アカウント連携、本人確認（機能仕様書 4.6.2）、表示するコンテンツの選択（4.6.3） |
| 入口 | 発信者メニューの「SNS」、発信者として登録の手順1 |

発信者メニューから開く「SNS」の画面は、もとの「SNS の連携」と「表示するコンテンツ」（2.3.3）を1つにまとめたもの（2026-11-19 本人：「発信者メニューは大事なものが多く詰まっているから、なるべくシンプルに整理したい」）。登録の手順から開いたときは、もとの「SNS の連携」のまま（出す内容の切り替えは出さない。まだ発信者がいないため）。

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「SNS」（登録の手順から開いたときは「SNS の連携」）。設定のアカウント（ログイン方法）と混ざらないよう、「アカウント連携」とは呼ばない（2026-11-10 本人）
- 説明「連携して、そのアカウントが本人のものだと確認されると、追星に表示できます。」。発信者メニューから開いたときは、その下に注記「オフにすると、取得済みの投稿も、すぐにファンに見えなくなります。」
- 発信者メニューから開いたときは、SNS ごとに面（角丸の灰色の面）を並べ、面の上に下の行、その下に出す内容のスイッチ（2.3.3 の決めのまま）を並べる。準備中の SNS の面は、行もスイッチも薄くし、スイッチはオフで操作できない。登録の手順から開いたときは、行だけを並べる
- SNS ごとの行（並びは画面定義書 5.1.7。準備中の SNS は最後に、Instagram・ツイキャス（v1.0.0 だけ）・TikTok・ニコニコの順）：アイコン、サービス名、アカウント名（「@{アカウント}」。未連携は「未連携」）、右に状態
  - 確認済み　→　チップ「確認済み」
  - 未連携、または連携済みで未確認　→　「連携する」（未確認なら、アカウント名も出す。押すと連携をやり直す）
  - **【仮】** Instagram の DM の確認を待っている（機能仕様書 4.6.2.1）　→　チップ「確認待ち」。アカウント名は、入れたアカウント
  - 対応していない SNS（TikTok・ニコニコ。v1.0.0 は Instagram も）　→　グレーアウトし、チップ「準備中」。押せない。アカウント名は「未連携」
- v1.0.0 では、Instagram の行を「準備中」にする（機能仕様書 4.6.2。次の版で出す）。確認済みの Instagram があっても同じ。DM の手順（下の【仮】）にも進まない。切り替えはアプリのコードの1か所だけで、サーバーの設定では切り替えない
- **【仮】**（次の版から）Instagram の行は、運営の受け先（サーバーの設定）があって、まだ確認が済んでいないとき、DM の手順にする。受け先がないときは、ほかの SNS と同じ連携（OAuth）にする。切り替えはサーバーの設定だけで行い、アプリは出し直さない
- 注記「確認が済んでいないアカウントは、追星には表示されません。連携したあとも、追星に出す内容をオフにできます。連携は、いつでも解除できます。」
- 読み込み中（Instagram の DM の状態を読み終えるまで。v1.0.0 は DM の状態を読まない）は、準備中以外の行を押せない

<kbd>遷移</kbd>

- 「連携する」　→　その SNS の連携（OAuth）へ。アプリ内のブラウザで、SNS のログインと許可の画面を開く。戻ると、スナックバー「{サービス名}を連携しました」。途中でやめたときは、何も出さない
- 登録の手順から開いて、連携したアカウントがオーナーの退会した発信者のものだった　→　「オーナーが退会した発信者のアカウントです。登録の画面から、取り戻せます」と出し、発信者として登録（2.2.1）に戻る
- **【仮】** Instagram の「連携する」・「確認待ち」（DM の手順のとき）　→　DM の確認のシート（2.3.2.1）
- 確認済みの行　→　連携の解除の確認ダイアログ（「{サービス名}の連携を解除しますか？」、「キャンセル」「解除する」）。本文は、発信者メニューから開いたときは「すぐに、追星に表示されなくなります。取得した投稿・配信・予定・実績は、90日残してから消します。90日のうちに、同じアカウントを連携し直すと、元に戻ります。」、登録の手順から開いたときは「追星に表示されなくなります。」。「解除する」で、本人の確認（シート。2.1.7）のあと、解除する。スナックバー「{サービス名}の連携を解除しました」

<kbd>異常系</kbd>

- 連携の一覧を読めない　→　状態表示（読み込めない）
- **【仮】** Instagram の受け先や DM の状態を読めない　→　OAuth に切り替えず、Instagram の行に「読み込めませんでした」と「再試行」（押せる連携の手順を決められないため）
- アカウントが、ほかの発信者で連携されている　→　スナックバー「このアカウントは、ほかの発信者で連携されています」
- YouTube で、チャンネルがない　→　スナックバー「YouTube のチャンネルが見つかりませんでした」
- 連携に失敗　→　スナックバー「連携できませんでした。もう一度お試しください」
- 解除に失敗　→　スナックバー「解除できませんでした。もう一度お試しください」

##### 2.3.2.1 【仮】Instagram の DM の確認のシート

> **これは仮の画面。** Meta の審査が通るまでの、一時的な代わり（機能仕様書 4.6.2.1）。審査が通ったら外す。

| 項目 | 内容 |
| --- | --- |
| 役割 | Instagram のアカウントを、DM で確かめる |
| 関連機能 | 【仮】Instagram の DM での確認 |
| 入口 | SNS の連携の Instagram の行（DM の手順のとき） |

<kbd>構成要素</kbd>

- 見出し「Instagram を DM で確認」
- コードを出す前：
  - 説明「Instagram のユーザー名を入れて、コードを出してください。そのアカウントから、運営の Instagram（@{受け先}）にコードを DM で送ると、運営が確かめて「確認済み」にします。」
  - ユーザー名の欄（ラベル「Instagram のユーザー名」。先頭に「@」）
  - 「コードを出す」（ユーザー名が空のあいだは押せない）
- コードを出したあと（確認待ち）：
  - 「確かめるアカウント：@{アカウント}」
  - コードと「コピー」
  - 「送り先：@{受け先}」
  - 「Instagram で DM を送る」（`https://ig.me/m/{受け先}` を開く）
  - 注記「運営が確かめるまで、数日かかることがあります。コードの期限は {日付} までです。」（期限は、コードを出した日の7日後）
  - 「取り消す」
- 処理中は、「コードを出す」「取り消す」を押せない

<kbd>入力項目・バリデーション</kbd>

- ユーザー名：英小文字・数字・`.`・`_` の1〜30文字（サーバーで、前後の空白と先頭の「@」を除き、小文字にそろえて確かめる）。

<kbd>遷移</kbd>

- 「コードを出す」　→　同じシートで、コードを出したあとの表示に変える
- 「コピー」　→　コードをコピーし、スナックバー「コードをコピーしました」
- 「Instagram で DM を送る」　→　Instagram（アプリかブラウザ）を開く
- 「取り消す」　→　コードを消し、シートを閉じる。行は「連携する」に戻る

<kbd>異常系</kbd>

- 読み込めない、または DM の手順が止められた（受け先がなくなった）　→　シートの本文に「コードを出せませんでした。もう一度お試しください」
- ユーザー名の形が違う　→　スナックバー「Instagram のユーザー名を確かめてください」
- ほかの発信者で連携されている　→　スナックバー「このアカウントは、ほかの発信者で連携されています」
- コードを出せない　→　スナックバー「コードを出せませんでした。もう一度お試しください」
- 取り消せない　→　スナックバー「取り消せませんでした。もう一度お試しください」
- Instagram を開けない　→　スナックバー「ページを開けませんでした」

#### 2.3.6 プラン

| 項目 | 内容 |
| --- | --- |
| 役割 | いまのプランを確かめる。X連携プランに加入・解約する |
| 関連機能 | プラン（機能仕様書 4.6.6） |
| 入口 | 発信者メニュー |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「プラン」
- 「いまのプラン」のカード：プラン名。基本プランなら「無料」と、使えること（「YouTube・Instagram・ツイキャス・Twitch の取得と表示」。v1.0.0 は「YouTube・Twitch の取得と表示」「配信の予約の取得」「イベントの登録」）。永年無料・運営・確認用なら「料金はかかりません（X の連携を含む）」
- 「オプション」：X連携プランのカード。月額（例：「月290円」）、特典（「X の投稿の取得と表示」「リポスト・リプライは、取りません」）。加入していなければ「加入する」。加入中なら、チップ「加入中」と「次の更新日 {日付}」（解約済みなら「{日付}に終了」）
- 「解約する」（X連携プランに加入中のとき、カードの下）
- 「購入を復元」
- 注記「お支払いは、ストアのアカウントに請求されます。X連携プランは、1か月ごとの自動更新のサブスクです。期間の終わりの24時間前までに解約しないと、自動で更新されます。解約は、ストアのサブスクの管理で行えます。」と、利用規約・プライバシーポリシーへのリンク（App Store の審査で必須）

<kbd>入力項目・バリデーション</kbd>

- 出し分け：
  - 永年無料・運営・確認用　→　「いまのプラン」のカードだけを出す
  - この端末で課金を使えない（機能仕様書 4.6.6）　→　「いまのプラン」のカードと、状態表示「この端末では、まだ X連携プランに加入できません」「準備ができるまで、お待ちください。」（ボタンなし）だけを出す
  - そのほか（基本プラン）　→　すべてを出す
- 月額は、ストアの価格を出す（国ごとに通貨が変わる）。日本円なら「{金額}円」の形にし、ほかの通貨はストアの書き方のままにする。ストアの価格を読めないときは、オプションのカードを出さない。表示するコンテンツ（2.3.3）の X の注記は、ストアの価格を読めないときだけ、アプリに持つ月額（290円）を出す。
- 加入中かどうか・次の更新日は、ストアの購入から決める（サーバーの加入の状態は、Webhook の分だけ遅れるため。機能仕様書 4.6.6）。

<kbd>遷移</kbd>

- 「加入する」　→　ストアの購入のシートを出す。購入が済んだら、X連携プランのカードを加入中の表示に変える（画面は閉じない）。シートを閉じたら、何もしない
- 「解約する」　→　確認のダイアログ（「ストアのサブスクの管理を開きます」「解約は、ストアの画面で行います。期間の終わりまでは、X の連携を使えます。」、「開く」「キャンセル」）。「開く」で、ストアのサブスクの管理の画面を開く（本人の確認は出さない。機能仕様書 4.1.4.1）
- 「購入を復元」　→　ストアの購入を読み直し、加入の状態を更新する。見つかれば、スナックバー「購入を復元しました」。見つからなければ「復元できる購入がありません」
- 規約・プライバシーポリシー　→　公開ページを開く

<kbd>異常系</kbd>

- 読み込み中　→　「いまのプラン」のカードと、その下にスケルトン
- 読み込めない（ストアの商品が見つからないときも）　→　「いまのプラン」のカードと、状態表示（読み込めない）
- 購入に失敗　→　スナックバー「購入できませんでした。もう一度お試しください」
- 支払いの承認を待つ（保護者の承認など）　→　スナックバー「支払いの承認を待っています」
- 解約の画面・公開ページを開けない　→　スナックバー「ページを開けませんでした」
- 復元に失敗　→　スナックバー「復元できませんでした。もう一度お試しください」

#### 2.3.7 イベントの管理

| 項目 | 内容 |
| --- | --- |
| 役割 | 自分のイベントの公演を一覧し、登録・編集の画面を開く |
| 関連機能 | イベント（機能仕様書 4.5.2） |
| 入口 | 発信者メニューの「イベントの管理」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「イベントの管理」、右に「登録」
- これからのイベントの公演を、日付の順に並べる。各行に、日時、タイトル、汎用のアイコン（イベントの印）、会場（あるときだけ）。日時は「{日付}{開始}〜{終了}」（終了がなければ「{日付}{開始}〜」）。時刻未定の公演は「{日付} 時刻未定」
- 「過去のイベント」：終わった公演を、新しい順にまとめる（はじめは閉じておき、押すと開く）。終わった公演は、終了の時刻を過ぎたもの（終了のない公演は、その日が終わったら終わったとみなす。2026-11-19 本人）と、前の日までの時刻未定の公演
- 取得した配信の予約は出さない

<kbd>遷移</kbd>

- 「登録」　→　イベントの登録へ（2.3.9）
- 各行　→　イベントの編集へ（2.3.9）
- 登録・編集・削除から戻る　→　一覧を読み直す

<kbd>異常系</kbd>

- 1件もない（過去のイベントもない）　→　状態表示（「イベントはまだありません」、「登録」ボタン）
- これからのイベントがなく、過去のイベントだけある　→　状態表示は出さず、閉じた「過去のイベント」だけを出す
- 読み込めない　→　状態表示（読み込めない）

#### 2.3.8 投稿の管理

| 項目 | 内容 |
| --- | --- |
| 役割 | 自分の投稿を一覧し、追星で隠す・また出す |
| 関連機能 | 投稿を隠す（機能仕様書 4.4.4） |
| 入口 | 発信者メニューの「投稿の管理」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「投稿の管理」
- 一覧の上に、注記「ここで隠しても、元の SNS の投稿は消えません。追星でファンに出さなくなるだけです。」（2026-11-19 本人）
- 自分の投稿を、新しい順に、600件まで並べる。出すのは、ファンに見えている投稿と、隠している投稿（表示するコンテンツでオフにした投稿と、X を取得しない発信者の X の投稿は出さない）
- 各行（コンパクトな行）に、投稿元のバッジ、「{種類} ・ {投稿からの時間}」、本文（なければ種類）、YouTube と Instagram はサムネイルを出す。X の投稿は、バッジの代わりに行の右端（右上）に「X の投稿者の行」（[画面定義書（ファン向け）](screen-design-fan.md) 2.2.1）を出し、時間の後ろに「· Xで見る」を出す。右端に、トグル（オン＝ファンに出す、オフ＝隠す。読み上げは「ファンに出す」）
- 隠している投稿の行：行を薄くし、トグルをオフにする
- 2026-11-19 に、「隠す」「また出す」のボタンをトグルに置き換えた（本人。ボタンよりオン・オフのほうが分かりやすいため）

<kbd>遷移</kbd>

- 各行　→　投稿ビューアへ（この一覧の順で、前後に移る。投稿者のアイコン・名前は押せない）
- トグルをオフ　→　確認のダイアログは出さず（オンに戻せるため）、投稿を隠して、行を隠している見た目にし、スナックバー「隠しました」
- トグルをオン　→　投稿をまた出して、行をふだんの見た目に戻し、スナックバー「また出しました」

<kbd>異常系</kbd>

- 1件もない　→　状態表示（「まだ投稿がありません」）
- 読み込めない　→　状態表示（読み込めない）
- 隠せない　→　トグルをオンに戻し、スナックバー「隠せませんでした」
- また出せない　→　トグルをオフに戻し、スナックバー「また出せませんでした」

#### 2.3.9 イベントの登録

| 項目 | 内容 |
| --- | --- |
| 役割 | 発信者が、イベント（ライブ・ツアーの1公演・トークイベントなど）を登録する。1つのイベントは、1つの公演（決定事項 1）。チケットの URL から、タイトル・日時・会場を読み取って下書きにできる |
| 関連機能 | イベント、URL からの読み取り（機能仕様書 4.5.2） |
| 入口 | イベントの管理（2.3.7）の「登録」。編集は、イベントの管理の各行、イベントの詳細・予定の詳細（シート）の「編集」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「イベントの登録」（編集のときは「イベントの編集」）、右に「保存」
- 「チケットサイトで探す」の行（新しく登録するときだけ）
- 「チケットの URL」：入力欄と「読み取る」（URL の欄が空のあいだは押せない）。注記「チケットのページを開いて、タイトル・日時・会場を読み取ります。読み取れなかった項目は、手で入れてください。」
- 「タイトル」（必須。プレースホルダ「例：新衣装のお披露目」）
- 「公演」：公演のカードを1つ。「日付」（必須）、「時刻未定」のスイッチ（補足「開演の時刻が決まっていない・分からない公演」）、「開始」（必須。時刻未定のときは不要）と「終了（任意）」（下に、注意書き「指定しない場合は、その日の終わりまで表示します」。2026-11-19 本人）、「会場（任意）」。時刻未定で、公演のページの URL があれば「ページから時刻を読む」
- 「チケットリンク」：リンクごとに、URL の欄、「このリンクは広告です」のスイッチ（補足「「PR」と表示します（チケットの販売など）」）、消すボタン。下に「＋ チケットリンクを足す」
- 編集のときは、一番下に「このイベントを消す」

<kbd>入力項目・バリデーション</kbd>

- タイトルは必須で、1〜200文字（見た目の1文字で数え、前後の空白は除く）。入力欄でも200文字で止める（機能仕様書 4.5.2）。
- 日付は必須。選べるのは、今日の365日前から730日後まで。編集で、入っている日付がその外なら、そこまで広げて選べる。
- URL（チケットの URL・チケットリンク）は、`https://` で始まるものだけ。
- 開始の選択の初期値は 18:00、終了は、入っている終了、なければ開始、それもなければ 20:00。
- 同じチケットのページを指すリンクは、この発信者のイベント全体で1本だけ（機能仕様書 4.5.2）。同じイベントの中に2本あれば、保存のときに1本にまとめる（どちらかが広告なら、広告にする）。
- 読み取った結果は、入力欄に上書きする（タイトル・公演は、読み取れたときだけ）。読み取りに使った URL（ページの中を移ってから読み取ったら、移った先のページの URL。読み取りにも、そちらを使う）は、まだなければチケットリンクに足す（空のリンクの欄があれば、そこへ入れる）。選んだ公演にページの URL があれば、そちらを足す。
- ページに公演が複数あれば、公演を選ぶ（2.3.14）で1つ選んでもらう。選ばずに閉じたら、公演は入れ替えない（タイトルの上書きと、リンクの追加はする）。開演が読み取れなかった公演は、開始を空のままにする。
- 「ページから時刻を読む」は、同じ日の公演の開演（同じ日の公演がなくても、開演の分かる公演が1つだけなら、その時刻）を、開始（と終了）に入れ、時刻未定を外す。

<kbd>遷移</kbd>

- 「チケットサイトで探す」　→　チケットサイトで探す（2.3.12）へ
- 「読み取る」　→　ページから読み取る（2.3.10）を開く。読み取れたら、入力欄を埋めて、スナックバー「読み取りました。内容を確かめてください」。ページから何も取り出せなければ、スナックバー「読み取れませんでした。手で入れてください」。ページのイベントから選んだときは、イベントの候補（2.3.11）を開き、戻ったら読み取りを終える
- 「ページから時刻を読む」　→　公演のページを、ページから読み取る（2.3.10。ボタンは「このページから時刻を読む」）で開く。時刻を読めたら、スナックバー「時刻を読み取りました」。読めなければ（通信の失敗も）「時刻を読み取れませんでした」
- 「保存」　→　保存できたら、前の画面に戻り、スナックバー「イベントを登録しました」（編集では「イベントを保存しました」）
- 「このイベントを消す」　→　確認のダイアログ（「このイベントを消しますか？」「公演とチケットリンクも消えます。」、「キャンセル」「削除」）のあと消して、前の画面に戻る（スナックバーは出さない）

<kbd>異常系</kbd>

- 必須の項目が足りない　→　欄に印を付け、スナックバー「必須の項目を入力してください」
- タイトルが200文字を超える　→　スナックバー「タイトルは、1〜200文字で入力してください」
- URL が `https://` で始まらない　→　欄の下に「https:// で始まる URL を入れてください」
- 同じチケットのページを指すリンクが、ほかのイベントにある　→　スナックバー「このチケットリンクは、ほかのイベントで登録済みです」
- 「読み取る」で、通信などに失敗　→　スナックバー「読み込めませんでした」
- 編集で、イベントを読み込めない　→　状態表示（読み込めない）
- 保存できない　→　スナックバー「保存できませんでした」
- 消せない　→　スナックバー「削除できませんでした」

#### 2.3.10 ページから読み取る

| 項目 | 内容 |
| --- | --- |
| 役割 | 発信者が、チケットのページをアプリの中で自分で開き、表示しているページから、イベントの下書きを読み取る |
| 関連機能 | URL からの読み取り（機能仕様書 4.5.2） |
| 入口 | イベントの登録（2.3.9）の「読み取る」「ページから時刻を読む」、イベントの候補（2.3.11）、公演の候補（2.3.13） |

<kbd>構成要素</kbd>

- 全画面で開く。ヘッダー：閉じる、タイトル（ページのドメイン。例：「t.pia.jp」。ページを移るたびに変わる）。読み込んでいるあいだは、読み込みの線を出す
- ページ：貼った URL を開く。発信者は、ページの中を見て回れる（ツアーのページに移るなど）。`https://` 以外のページには移らない
- 下に「このページから読み取る」（ページを読み込んでいるあいだは押せない）と、注記「表示しているページから、タイトル・日時・会場を読み取ります。」
- 表示しているページに、イベントのページへのリンクがあれば、読み込み終えたあと、その下に「このページのイベントから選ぶ（{N}件）」（検索結果・アーティストのページなど）。拾うリンクの形は、チケットサイトごとに決めている（技術検証 2.16）
- イベントの候補から開いたときは、ボタンを「このイベントを登録」にし、「ページから時刻を読む」から開いたときは「このページから時刻を読む」にする。どちらも、候補は拾わない

<kbd>遷移</kbd>

- 「このページから読み取る」　→　表示しているページから、読み取りに要る部分だけを取り出してサーバーに送り（機能仕様書 4.5.2）、イベントの登録に戻る。ページ全体は送らない（ログインしていると、会員の名前などが出るため）
- 「このページのイベントから選ぶ」　→　イベントの候補（2.3.11）へ。リンクは、ページに出ている分だけを拾い、自動ではたどらない
- 閉じる　→　読み取らずに、元の画面に戻る

#### 2.3.11 イベントの候補

| 項目 | 内容 |
| --- | --- |
| 役割 | 検索結果やアーティストのページにあった、イベントのページへのリンクを並べる。発信者が1件ずつページを開いて確かめ、ワンタップで登録する |
| 関連機能 | イベント、URL からの読み取り（機能仕様書 4.5.2） |
| 入口 | ページから読み取る（2.3.10）の「このページのイベントから選ぶ」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「イベントの候補」
- 注記「押すとページを開きます。内容を確かめて、「このイベントを登録」を押してください。」。候補が1件もないときは、代わりに「イベントが見つかりませんでした」
- 候補の行：リンクの文字（チケットサイトに書いてあるまま）、リンクのそばにある公演の日付と会場（会場ごとに日付をまとめる。例：「2026/11/12(木)・11/13(金) NIIGATA LOTS (新潟県)」）、サイトの名前。登録済み（同じチケットのページを指すリンクが、この発信者のイベントにある）なら、チップ「登録済み」

<kbd>遷移</kbd>

- 候補の行　→　ページから読み取る（2.3.10。ボタンは「このイベントを登録」）を開く。発信者が自分でページを確かめる
- 「このイベントを登録」　→　読み取った内容で、すぐイベントを登録する（リンクは、公演のページの URL、なければその候補の URL）。ページに公演が複数あれば、公演を選ぶ（2.3.14）で1つ選んでもらう（選ばずに閉じたら、登録しない）。開演が読み取れなかったら「時刻未定」にする。登録できたら、この一覧のまま、スナックバー「イベントを登録しました」（時刻未定なら「イベントを登録しました。時刻未定の公演は、編集で時刻を足せます」）。その候補の行を「登録済み」にする
- タイトルか公演が読み取れない、またはタイトルが200字を超える　→　イベントの登録（2.3.9）を下書き入りで開き、発信者が足して（直して）保存する。戻ったら、登録済みかを読み直す
- 登録済みの行　→　押せる（ページのほかの公演を、別のイベントとして登録できる）

<kbd>異常系</kbd>

- 読み取れない（通信の失敗も）　→　スナックバー「読み取れませんでした。手で入れてください」と出し、イベントの登録（2.3.9）を、リンクだけ入れて開く
- 同じチケットのページを指すリンクが、ほかのイベントにある　→　スナックバー「このチケットリンクは、ほかのイベントで登録済みです」
- 登録できない　→　スナックバー「保存できませんでした」

#### 2.3.12 チケットサイトで探す

| 項目 | 内容 |
| --- | --- |
| 役割 | 発信者が、アーティスト名でチケットサイトを検索し、ヒットしたアーティストを選んで、公演の候補（2.3.13）を出す |
| 関連機能 | イベント（機能仕様書 4.5.2「チケットサイトで探す」） |
| 入口 | イベントの登録（2.3.9）の「チケットサイトで探す」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「チケットサイトで探す」
- 「アーティスト名」の入力欄（初期値は、発信者の名前）と「探す」（キーボードの検索のキーでも探す）
- 注記「チケットぴあ・イープラス・ローチケ・楽天チケットで、この名前のアーティストを探します。同じ名前の別の人も出るので、確かめてから選んでください。」
- 結果（「探す」を押したあとに出す）：サイトごとの見出し（「チケットぴあ」「ローチケ」「イープラス」「楽天チケット」の順）の下に、ヒットしたアーティストの行（選ぶチェック、名前、サイトの名前）。1サイト30人まで。探しているあいだは、サイトごとに読み込み中の表示を出す
  - 楽天チケットは、アーティストの単位がないので、「「{名前}」を含むイベント（{N}件）」の1行を出す
- 下に「公演を見る（{N}件）」（「探す」を押したあとに出す）

<kbd>入力項目・バリデーション</kbd>

- 名前が空のあいだ、探しているあいだは、「探す」を押せない。
- 探し直すたびに、選んだものを消す。
- はじめから選んでおくのは、入れた名前と同じ名前のアーティスト（大文字・小文字と空白の違いは見ない）。同じ名前がなければ、括弧の補足（「(アイドルVtuber)」など）と記号を除いて1人だけ合うとき。2人以上なら、同じ名前の別人かもしれないので選ばない。楽天チケットの1行も、はじめから選んでおく。
- 「公演を見る」は、1件も選んでいないとき、探しているあいだは押せない。

<kbd>遷移</kbd>

- 「探す」　→　4つのサイトの検索結果のページを、画面に出さずに開き、アーティストのページへのリンクを並べる
- 「公演を見る」　→　公演の候補（2.3.13）を、選んだアーティストで開く

<kbd>異常系</kbd>

- ヒットしない　→　そのサイトの見出しの下に「アーティストが見つかりませんでした」
- サイトを開けない（時間切れも）　→　そのサイトの見出しの下に「読み込めませんでした」
- サイトがメンテナンス中（メンテナンスのお知らせのページに転送された。チケットぴあは深夜に定期のメンテナンスがある）　→　そのサイトの見出しの下に「メンテナンス中のため、いまは探せません」

#### 2.3.13 公演の候補

| 項目 | 内容 |
| --- | --- |
| 役割 | 選んだアーティストの公演を、サイトを横断して1日1行で並べる。発信者が1件ずつ公演のページを開いて確かめ、ワンタップで登録する |
| 関連機能 | イベント（機能仕様書 4.5.2「チケットサイトで探す」） |
| 入口 | チケットサイトで探す（2.3.12）の「公演を見る」 |

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「公演の候補」
- 読み込んでいるあいだは、読み込み中の表示と「公演を集めています（{n}/{N}）」（N は開くページの数。イベントのページが見つかるたびに増える）
- 注記「押すと公演のページを開きます。内容を確かめて、「このイベントを登録」を押してください。」。公演が1つもないときは、代わりに「公演が見つかりませんでした」
- 公演の行（日付の順。同じ日は開演の順で、開演が分からないものは後ろ）：ファンのイベントの行と同じ形。日付のブロック（月・日）、イベントの名前、「{曜日}・{会場}」（会場がなければ曜日だけ）、売っているサイトの名前（「チケットぴあ・イープラス」）。登録済みなら、チップ「登録済み」
- 読めなかったページがあれば、一覧の下に「読み込めなかったページが {n} 件あります」と「再試行」

<kbd>集め方</kbd>

- 選んだアーティストのページから、イベントのページ（と公演ごとのページ）へのリンクを拾い、イベントのページを、画面に出さずに1ページずつ開いて、公演（日付・開演・会場・公演のページの URL）を拾う。抜け漏れがないよう、受付が終わった公演も拾う。アーティストのページにある、ほかのサイト（ZAIKO・LivePocket など）のイベントへのリンクは拾わない（そのサイトの拾い方で読むため）。イベントのページより先はたどらない。ページを開くのは、発信者が「公演を見る」を押したときだけ（機能仕様書 4.5.2）。
- 今日より前の公演は出さない。
- シャトルバス・駐車券・グッズ・物販・入店整理券などの、公演でない券は拾わない。
- 同じ公演を複数のサイトが売っていれば、1行にまとめる。同じ日で、会場が同じとみなせて、開演の時刻が食い違わないもの（どちらかが分からない・同じ）を、同じ公演とみなす。開演の時刻が違えば、昼夜の公演として別の行にする。開演や会場が分からない公演は、同じ日の公演のどれかにまとめる。
- イベントの名前は、イベントのページの名前を使う（アーティストのページにある名前は、販売の名前のため）。
- サイトごとの拾い方・会場名の比べ方は、技術検証 2.16 とコードを正とする。

<kbd>遷移</kbd>

<kbd>画像</kbd>

- 大きさ：横長 16:9（1200×675。テンプレは 1600×900 で組み、縮めて書き出す。本番の CPU の上限に入れるため。tech-risks 2.39）。X に貼る前提（配信者の週間の予定の告知は、X に 16:9 で貼るのがよくある形のため）

  - 背景：同じ画像を強くぼかして、黒の 45% で暗くした色を、左から右へ8か所拾った横のグラデーション（色が画像に合う。ぼかした画像を全面に敷く形は、描くのが重く本番の CPU の上限を超えたのでやめた。tech-risks 2.39）
  - 7日の予定：右側に、白い角丸の面（不透明度 94%）で浮かせて置く。影は付けない（サーバーで作る時間が倍になるため。tech-risks 2.39）。左の端は、画像の溶けかけた所に少し重ねる。下に追星の名前を白い文字で小さく置く
  - 7日の行：日付と曜日、その日の予定を2件まで（時刻・題名）。3件目からは「ほか N 件」。予定がない日は「—」、週に1件もなければ月曜の行に「予定はまだありません」
- アイコンは、取れる一番大きい画像を使う。X は `_400x400` などの印を外した元の大きさ、YouTube は `=s1200`。開けなければ、持っているアイコンの URL に戻す
- 画像が無い（開けない）とき：淡い紫の地に、追星の星のキャラクター（青）を置く
- 名前の絵文字は、今は落として描く（フォントに無いため）
- 画像に、追星の QR とリンクの文字は入れない（2026-11-19 本人：「画像内に追星の URL やコードは不要」）。予定ごとの URL と誘う用のリンクは、一緒に共有する文に入れる（届ける・広める仕様書 4.4.1）

| 役割 | 発信者のオーナーが、リンク集のリンクを足し、題名と URL を直し、並べ替え、消す |
| 関連機能 | リンクの登録・押された数（届ける・広める仕様書 4.6.1・4.6.3） |
| 入口 | リンク集（2.3.17）の「編集」 |

見た目は、Figma を飛ばし、今の画面（届いた数・投稿の管理）の部品にそろえた仮の決め（2026-11-18）。もとはリンク集の画面にあった編集を、ここへ移した（2026-11-19 本人）。

<kbd>構成要素</kbd>

- ヘッダー：戻る、タイトル「リンク集を編集」、右に「追加」。10件あれば押せない
- 説明「発信者ページと共有のページに、ボタンで並びます。」
- つないだ SNS（本人確認済み）のリンクは、サーバーが最初から入れておく（題名はサービス名。届ける・広める仕様書 4.6.5）。ふつうのリンクと同じく、並べ替え・編集・削除できる。消したあとは、また入らない
- リンクの一覧（面）：1件1行。左に並べ替えのつまみ、題名、その下に行き先のドメイン、右に押された数（「{N}回」。3桁区切り）
- 1件もなければ「まだリンクがありません。好きなリンクを足すと、発信者ページに並びます。」と「リンクを追加」のボタン
- 注記「押された数は、アプリと共有のページで押された回数の合計です。URL を変えると0に戻ります。誰が押したかは出しません。」
- 10件のときは、一覧の下に「リンクは10件までです」

<kbd>遷移</kbd>

- 「追加」　→　リンクの追加・編集（シート。2.3.18）を、空で出す
- 行　→　リンクの追加・編集（シート）を、その行の値で出す
- つまみをつかんで動かす　→　並びを変えて、すぐ保存する
- 行を左へ払う　→　「削除」。押すと確認（「「{題名}」を消しますか？」「押された数も消えます。」、「削除」「キャンセル」）
- 下に引く　→　読み直す
- 戻る　→　リンク集（2.3.17）

<kbd>異常系</kbd>

- 読み込めない　→　状態表示（読み込めない）。「もう一度試す」
- 並べ替え・削除に失敗　→　スナックバー「保存できませんでした」。保存されている内容を読み直して出す
